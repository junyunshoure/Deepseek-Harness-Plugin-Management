# 服务部署指南（Windows）

适用：DeepSeek Harness 桌面版 **0.2.x** + 插件整合包 **v2.0.0** + 服务本体包 **v2.0.0**。
本文件位置：解压目录下的 `docs\服务部署指南.md`。命令默认粘进 **PowerShell** 执行；`%USERPROFILE%` = `C:\Users\<你>`，`%LOCALAPPDATA%` = `C:\Users\<你>\AppData\Local`。
事实来源：服务包 `payload\services\manifest.json`、`SETUP-SERVICES.ps1`、`payload\services\weknora\README.md`、插件包 `config\feature-profiles\reme.md|openviking.md|hindsight.md|weknora.md`。行内标「推断」的条目是按上述文件推出来的、没有在本机实测过。

---

## 0. 三十秒版本

1. 装插件包 → DSH 正常用，只是本地记忆/知识库报连接失败（**这是预期**）。
2. 想要记忆能力 → 解压 `DSH-Plugins-v2.1.3-Services.zip`，双击里面的 `SETUP-SERVICES.cmd`。
3. 想自动整理记忆 → 再设 4 个 `LLM_*` 环境变量，重启 ReMe；想要组织知识库 RAG → 另外在 WSL 里跑 WeKnora，占 8080。

## 1. 先分清：「插件包」和「服务本体包」是两个独立压缩包

| | 插件整合包 `DSH-Plugins-v2.1.3-Windows-x64.zip` | 服务本体包 `DSH-Plugins-v2.1.3-Services.zip`（版本号与插件包同步 2.1.3） |
| --- | --- | --- |
| 内容 | 32 个插件 + 6 个技能 + 47 篇功能 profile 说明 + 配置骨架 | 独立 CPython 312/314 + ReMe / OpenViking / Hindsight 的 site-packages 快照 + 启动器 + WeKnora 说明 |
| 大小量级 | 几十 MB 级（插件本体） | 约 1.9 GB（ReMe 1.2 GB + OpenViking 0.6 GB 为主） |
| 装完有没有服务 | **没有**，一个后台进程都不会起 | 有，2333 / 1933 / 8888 三个常驻（WeKnora 手动） |
| 不装会怎样 | —— | DSH 完全正常，只是记忆/知识库功能不可用 |

`manifest.json` 的 `note` 原文就是这句话：**「这是「服务本体」可选包。插件整合包不含这些运行文件，两者互相独立：只装插件也能正常用 DSH，只是本地记忆/知识库相关功能不可用。」**

所以两种「报错」都不用慌：

- **只装插件包**：界面里「记忆融合 / Hindsight / knowledge」等入口报连接失败、超时、`ECONNREFUSED`。原因就是 2333/1933/8888/8080 没人监听，**属预期**，不是装坏了。
- **只装服务包**：端口起来了，但 DSH 里没有对应入口（插件没装，没人去调这些端口）。

两边都装齐，入口才真正可用。想确认现在到底是哪一半缺了，双击插件包里的 `DOCTOR.cmd`，它会打印一行 `本地记忆服务：ReMe(2333)=在线/离线 …`。

## 2. 四个服务一张总表

| 服务 | 作用 | 端口 | Windows 怎么装 | 额外依赖 | 数据目录 | 日志位置 | 卸载方法 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **ReMe** 自动记忆 | 检索个人历史/偏好/决定/待办；后台把对话整理成记忆 | 2333 | 服务包一键（`-Only reme`） | `LLM_BACKEND` / `LLM_BASE_URL` / `LLM_MODEL_NAME` / `LLM_API_KEY`（不设只失去「自动整理」） | `%USERPROFILE%\.dsh\memory\reme` | `%USERPROFILE%\.dsh\services\reme\logs\out.log`、`logs\err.log`；服务根目录另有 `service.out.log` / `service.err.log` | `stop.cmd` → 删 `%USERPROFILE%\.dsh\services\reme`（数据目录想清就一起删） |
| **OpenViking** 记忆库与共享技能 | 持久资料、经验记忆、共享技能、资源检索（`viking://` 体系） | 1933 | 服务包一键（`-Only openviking`） | 无；首次启动自动生成 `ov.conf` | `%USERPROFILE%\.openviking`（含 `data\`、`state\`、`pending\`、`ov.conf`） | `%USERPROFILE%\.dsh\services\openviking\logs\`、服务根 `service.*.log` | `stop.cmd` → 删 `%USERPROFILE%\.dsh\services\openviking`；数据在 `~\.openviking`，要清单独删 |
| **Hindsight** 项目知识页 | 每个仓库的知识页、历史决定、实施经验、`hindsight_*` 工具后端 | 8888 | 服务包一键（`-Only hindsight`） | 无；自带 `profile create` / `daemon start` | `%USERPROFILE%\.dsh\services\hindsight`（`profiles\`、`coding-agents-logs\`、`coding-agent.json`） | 同上 `logs\` + 服务根 `service.*.log` | `stop.cmd` → 删 `%USERPROFILE%\.dsh\services\hindsight` |
| **WeKnora** 组织知识库 RAG | 对组织文档做混合检索，原文片段 + 带引用综合回答 | 8080 | **手动**：WSL 里构建并运行（见第 6 节） | WSL2 + Ubuntu + Go 工具链 + git | WSL 内 `~/weknora` | WSL 内 `~/weknora/server.log` | WSL 里 `kill` 进程 → 删 `~/weknora` |

端口是 `manifest.json` 写死的默认值；`health` 字段就是下文的健康检查 URL。

## 3. 一键安装（ReMe / OpenViking / Hindsight）

### 3.1 步骤

1. 用 7-Zip 把 `DSH-Plugins-v2.1.3-Services.zip` 解到**短路径**，例如 `D:\DSHPack-Services`（Windows 自带解压对长路径不友好）。
2. 双击解压目录里的 `SETUP-SERVICES.cmd`（它会 `powershell -NoProfile -ExecutionPolicy Bypass -File SETUP-SERVICES.ps1 %*`）。
3. 屏幕先打印 `将安装：ReMe 自动记忆(2333)、OpenViking 记忆库(1933)、Hindsight 项目记忆(8888)`，然后逐个服务滚日志，最后打印「服务安装结果」。
4. 结果同时落盘：`%USERPROFILE%\.dsh\services-install-result.json`，形如
   `{"ok":true,"when":"2026-10-28T12:34:56","packRoot":"D:\\DSHPack-Services","results":[{"id":"reme","status":"ok","port":2333,"pid":12345,"path":"C:\\Users\\<你>\\.dsh\\services\\reme"}]}`
   `status` 取值：`ok` 已安装并在线 / `already` 之前装过本次跳过 / `unhealthy` 已启动但健康检查没过 / `failed` 安装失败（带 `error`）。

### 3.2 它到底做了什么（按脚本顺序）

| 步 | 动作 | 落地结果 |
| --- | --- | --- |
| 1 | 读 `payload\services\manifest.json`，按 `-Only` 过滤（`manual:true` 的 WeKnora 永远跳过） | 决定这次装哪几个 |
| 2 | `robocopy` 复制独立 CPython | `%USERPROFILE%\.dsh\runtime\python312` 与 `...\python314`（ReMe / OpenViking 用 312，Hindsight 用 314） |
| 3 | 用这份 Python 建虚拟环境：`python.exe -X utf8 -m venv <target>\.venv` | `%USERPROFILE%\.dsh\services\<id>\.venv` |
| 4 | 把 `payload\services\<id>\site-packages` 快照整目录灌进 venv | `<target>\.venv\Lib\site-packages`（ReMe 约 1.2 GB，需要几分钟） |
| 5 | 复制 Python 启动器 + 生成 4 个脚本 | `<target>\launch\<launcher>.py`、`start.cmd`、`start.ps1`、`stop.cmd`、`stop.ps1` |
| 6 | 真启动一次并做健康检查（最多 45 秒，HTTP 200–499 视为在线） | `<target>\service.pid`、`logs\out.log`、`logs\err.log` |

`start.ps1` 用 `Start-Process -WindowStyle Hidden` 起 `<target>\.venv\Scripts\python.exe`，把 stdout/stderr 重定向进 `logs\`，PID 写 `service.pid`；`stop.ps1` 读 `service.pid` 后 `Stop-Process -Force` 并删掉 pid 文件。所以**手动起的进程没有 pid 文件，`stop.cmd` 停不掉**。

### 3.3 参数

```powershell
# 只装 ReMe 和 OpenViking（想省 9 MB 的 hindsight 快照就这么写）
powershell -NoProfile -ExecutionPolicy Bypass -File .\SETUP-SERVICES.ps1 -Only reme,openviking

# 已装过也要重装（会先删掉该服务的 .venv 再重建）
powershell -NoProfile -ExecutionPolicy Bypass -File .\SETUP-SERVICES.ps1 -Only reme -Force

# 全自动：不问模型凭据，直接跳过那一段（适合脚本/远程）
powershell -NoProfile -ExecutionPolicy Bypass -File .\SETUP-SERVICES.ps1 -Auto

# 组合
powershell -NoProfile -ExecutionPolicy Bypass -File .\SETUP-SERVICES.ps1 -Only reme,hindsight -Force -Auto
```

### 3.4 一个容易踩的坑

插件包根目录**也有**一个 `SETUP-SERVICES.cmd`，但它转给 `install-helper.cjs --services-only`，而那段代码要求持久目录里存在 `payload\services\install-services.cjs`；服务本体包提供的是 `SETUP-SERVICES.ps1`，**不含** `install-services.cjs`（遍历 `_build-v2.0.0` 全树无此文件）。所以：**装服务请用服务包自己的 `SETUP-SERVICES.cmd`**；插件包那个同名文件只会打印一段「这个包里没有服务本体」的提示。

## 4. ReMe 的模型环境变量（为什么必须设）

插件只负责**触发**（对话结束后 POST `/auto_memory`），真正把对话压缩成记忆条目是 ReMe 自己去调模型。所以模型凭据必须交给 ReMe，而它只认 4 个环境变量：

| 变量 | 取值示例 | 说明 |
| --- | --- | --- |
| `LLM_BACKEND` | `openai` | OpenAI 兼容协议；安装器固定写这个值 |
| `LLM_BASE_URL` | `https://YOUR-ENDPOINT.example.com/v1` | 中转站或官方地址，**要带 `/v1`** |
| `LLM_MODEL_NAME` | `deepseek-v4.1-flash` | 必须与中转站里的模型名一致 |
| `LLM_API_KEY` | `sk-YOUR-KEY` | 密钥；安装器用 `SetEnvironmentVariable(...,'User')` 写到用户级 |

```powershell
setx LLM_BACKEND openai
setx LLM_BASE_URL "https://YOUR-ENDPOINT.example.com/v1"
setx LLM_MODEL_NAME "deepseek-v4.1-flash"
setx LLM_API_KEY "sk-YOUR-KEY"
# setx 只影响新进程：必须重启 ReMe 才生效
& "$env:USERPROFILE\.dsh\services\reme\stop.cmd"
& "$env:USERPROFILE\.dsh\services\reme\start.cmd"
```

安装器默认会问一次（直接回车 = 跳过）；`-Auto` 时整段跳过，之后随时可用 `setx` 补。

**不设的后果**：ReMe 在线、检索也正常，但自动整理会不断重试并报 `Missing credentials`，`logs\` 里的单文件能涨到几 MB 甚至更大（本机实测出现过 5.6 MB 与 4.1 MB 的单日日志）。这类日志同时会把真正的问题埋掉，建议先设凭据再排障。另有一条无害噪音：`Agent default exceeds the max iteration numbers 30. Stop the react loop.` 是模型回合超限的告警，不影响健康状态。

## 5. 逐服务手册

### 5.1 ReMe（2333）

```powershell
& "$env:USERPROFILE\.dsh\services\reme\start.cmd"          # 启动
& "$env:USERPROFILE\.dsh\services\reme\stop.cmd"            # 停止
Get-Content "$env:USERPROFILE\.dsh\services\reme\logs\err.log" -Tail 50 -Wait   # 看日志
# 健康检查：GET 会返回 405，必须 POST 空 JSON
Invoke-WebRequest http://127.0.0.1:2333/health_check -Method POST -ContentType 'application/json' -Body '{}' -UseBasicParsing |
  Select-Object -ExpandProperty Content
# 期望：{"answer":"✅ ReMe v0.4.2.0 - healthy","success":true, ...}
```

常见失败：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动即退，`err.log` 有 `Address already in use` | 2333 被占 | `Get-NetTCPConnection -State Listen -LocalPort 2333 \| Get-Process` 找出占用者 |
| `ModuleNotFoundError: xxx` | `.venv` 里 site-packages 快照灌了一半 | `-Only reme -Force` 重装 |
| 健康检查 200 但自动记忆不动 | `LLM_*` 没设或改了没重启 | 见第 4 节 |
| `Missing credentials` 刷屏 | 同上 | 同上 |

手动重装：`powershell -ExecutionPolicy Bypass -File .\SETUP-SERVICES.ps1 -Only reme -Force`（会删掉旧 `.venv`，`~\.dsh\memory\reme` 里的记忆数据不动）。

### 5.2 OpenViking（1933）

```powershell
& "$env:USERPROFILE\.dsh\services\openviking\start.cmd"
& "$env:USERPROFILE\.dsh\services\openviking\stop.cmd"
Get-Content "$env:USERPROFILE\.dsh\services\openviking\logs\err.log" -Tail 50 -Wait
Invoke-WebRequest http://127.0.0.1:1933/health -UseBasicParsing | Select-Object -ExpandProperty Content
# 期望：{"status":"ok","healthy":true,"version":"0.5.2","auth_mode":"dev"}
```

常见失败：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 1933 不通 | 服务没起 | 先看 `logs\err.log` 首屏 |
| 首次启动慢于 45 秒（健康检查报 `unhealthy`） | 首次要建 `~\.openviking` 的索引目录 | 等 1 分钟再检查一次；仍是红的就 `-Force` 重装 |
| `auth_mode` 不是 `dev` 且调用 401 | `ov.conf` 被改过 | 备份后删 `%USERPROFILE%\.openviking\ov.conf` 让它重生成（推断：会丢掉自定义认证配置） |
| 检索返回空 | 库是空的，没 `add_resource` / `remember` 过 | 不是故障 |

手动重装：`-Only openviking -Force`。数据在 `%USERPROFILE%\.openviking`，与安装目录分离，重装不丢。

### 5.3 Hindsight（8888）

```powershell
& "$env:USERPROFILE\.dsh\services\hindsight\start.cmd"
& "$env:USERPROFILE\.dsh\services\hindsight\stop.cmd"
Get-Content "$env:USERPROFILE\.dsh\services\hindsight\logs\err.log" -Tail 50 -Wait
Invoke-WebRequest http://127.0.0.1:8888/health -UseBasicParsing | Select-Object -First 1
```

常见失败：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 8888 上 `/health` 有响应，但 `hindsight_*` 工具仍报后端不对 | **端口被别人占了**：AnythingLLM 等工具默认也走 8888（本机实测占用者进程名 `AnythingLLM`） | `Get-NetTCPConnection -State Listen -LocalPort 8888 \| Get-Process` 认人；让 Hindsight 换端口（它自带换端口提示）或先停掉占用者 |
| `logs\err.log` 提到 Python 3.14 语法/ABI 问题 | Hindsight 用 `python314`，与其它两个不同 | 确认 `%USERPROFILE%\.dsh\runtime\python314\python.exe` 存在；缺了就 `-Only hindsight -Force` |
| 知识页一直空 | 仓库还没 `hindsight_capture_initiative` / 没跑过 agent 会话 | 不是故障，先让 agent 干活 |

手动重装：`-Only hindsight -Force`。数据在 `%USERPROFILE%\.dsh\services\hindsight\profiles`，重装不删。

### 5.4 三个服务共用的三条判据

- **端口不通**：`Get-NetTCPConnection -State Listen -LocalPort <port>` 有没有行 → 没有就翻 `logs\err.log` 尾部。
- **Python 缺库**：`err.log` 里出现 `ModuleNotFoundError` → 快照没灌完，`-Force` 重装。
- **模型连不上**：`Test-NetConnection` 打 `LLM_BASE_URL` 的主机 → 再确认 `setx` 之后重启过服务、地址没漏 `/v1`。

## 6. WeKnora：为什么单独讲

- 它是 **Go 编译的 Linux 服务**（`WeKnora-lite` 约 276 MB），没有 Windows 原生分发包；塞不进一个 Windows 一键脚本。
- 官方形态是跑在 **WSL（Ubuntu）** 里，Windows 侧的插件通过 `http://127.0.0.1:8080` 访问——WSL2 会自动把 127.0.0.1 转发进发行版（本机实测 8080 的监听者就是 `wslrelay`），所以「Linux 服务 + Windows 插件」是完全正常的组合。

三条构建命令（在 WSL 里）：

```bash
git clone https://github.com/Tencent/WeKnora.git ~/weknora
cd ~/weknora/src/WeKnora && cp .env.lite.example .env.lite
make build-lite && ./WeKnora-lite > ~/weknora/server.log 2>&1 &
```

`.env.lite` = 精简版配置：端口、模型与向量库凭据、数据落盘位置。想改端口或接自己的模型就改它，改完重跑 `./WeKnora-lite`。

Windows 侧验证与排查：

```powershell
Test-NetConnection 127.0.0.1 -Port 8080
Invoke-WebRequest http://127.0.0.1:8080/health -UseBasicParsing | Select-Object -ExpandProperty Content   # {"status":"ok"}
```

端口不通的三种原因：

| 原因 | 判据 | 处理 |
| --- | --- | --- |
| 服务压根没起 | WSL 里 `curl -s http://127.0.0.1:8080/health` 也不通 | 看 `~/weknora/server.log` 尾部；`ps aux \| grep WeKnora` |
| 只监听了 WSL 回环 | WSL 内通、`Test-NetConnection` 不通 | `.wslconfig` 加 `localhostForwarding=true`；或服务改监听 `0.0.0.0` 后用 WSL 的 IP 访问（`ip addr show eth0`） |
| Windows 侧 8080 已被占 | `Get-NetTCPConnection -State Listen -LocalPort 8080 \| Get-Process` | 停掉占用者，或改 `.env.lite` 端口并同步改 DSH 里的 WeKnora 地址 |

## 7. 开机自启：三种做法

| 做法 | 优点 | 缺点 |
| --- | --- | --- |
| **任务计划程序** | 可设「登录时」「延迟 30 秒」「最高权限」；失败可查历史 | 要手动建一次；改参数要去任务属性里翻 |
| **启动文件夹放 `START-ALL.cmd`** | 最简单，复制快捷方式即可 | 无延迟、无重试、无日志；三个服务同时起会有磁盘抖动 |
| **手动** | 零副作用，只在真要记忆功能时占资源 | 每次要记得双击 |

### 7.1 任务计划程序（推荐）

```powershell
# 图形版：Win+R → taskschd.msc → 创建任务
#   常规：名称 DSH-Services；勾「不管用户是否登录都运行」按需
#   触发器：新建 → 「登录时」→ 延迟 30 秒
#   操作：启动程序 → D:\DSHPack-Services\START-ALL.cmd
#   起始于：D:\DSHPack-Services
# 命令行版（等价）：
schtasks /Create /TN "DSH-Services" /SC ONLOGON /RL LIMITED /DELAY 0000:30 /TR "\"D:\DSHPack-Services\START-ALL.cmd\"" /F
```

`START-ALL.cmd` 会依次 `call` 三个服务的 `start.cmd`（reme → openviking → hindsight），末尾提示 `端口：2333 / 1933 / 8888`。停止用同目录的 `STOP-ALL.cmd`——它只停通过 `start.cmd` 起的进程。

### 7.2 启动文件夹

```powershell
shell:startup            # 在资源管理器地址栏输入，回车打开 %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup
# 把 START-ALL.cmd 的快捷方式丢进去即可
```

### 7.3 手动

只在需要时双击单个服务的 `start.cmd`。想让 DSH 一启动就有记忆，就在开 DSH 之前点一下；用完 `stop.cmd`。

## 8. 资源占用与取舍

| 项 | 磁盘 | 内存常驻 |
| --- | --- | --- |
| ReMe 依赖快照 | **约 1.2 GB**（实测 1217.9 MB） | 数百 MB 级；本机实测一个 python 进程 80 MB，跑整理/嵌入时会涨上去（推断：取决于 embedding 模型与记忆条数） |
| OpenViking 依赖快照 | **约 0.6 GB**（实测 603.2 MB） | 数百 MB 级；本机实测 485 MB |
| Hindsight 依赖快照 | 约 10 MB（实测 9.9 MB，服务本体在 daemon 里） | 百 MB 级（推断） |
| 独立 CPython 312 / 314 | 51.8 MB / 48.2 MB | 只在服务进程里体现，不额外常驻 |
| WeKnora | WSL 里约 276 MB 二进制 + 向量库数据 | 数百 MB（Go 服务，推断） |

取舍建议：

- **只要「记得我上次说过什么」** → 只装 ReMe（1.2 GB 是主要成本）。
- **要跨项目共享资料/技能** → 加 OpenViking。
- **要每仓库知识页** → 加 Hindsight（最便宜，10 MB 级）。
- **要组织文档 RAG** → 才上 WeKnora（成本在 WSL 与向量库）。
- **按需启动**：不常用就别设开机自启。写个 `NEED-MEMO.cmd` 只 `call` reme 的 `start.cmd`，用完 `stop.cmd`；DSH 在服务离线时只是对应入口报连接失败，其它功能不受影响。

## 9. 卸载与迁移

```powershell
# 1) 停服务
& "$env:USERPROFILE\.dsh\services\reme\stop.cmd"
& "$env:USERPROFILE\.dsh\services\openviking\stop.cmd"
& "$env:USERPROFILE\.dsh\services\hindsight\stop.cmd"
# 2) 删服务本体（数据目录分开，想留就留）
Remove-Item "$env:USERPROFILE\.dsh\services\reme","$env:USERPROFILE\.dsh\services\openviking","$env:USERPROFILE\.dsh\services\hindsight" -Recurse -Force
# 3) 三个服务都不用了，运行时也可以删
Remove-Item "$env:USERPROFILE\.dsh\runtime" -Recurse -Force
# 4) 安装记录
Remove-Item "$env:USERPROFILE\.dsh\services-install-result.json" -Force
```

- 只删 `services\<id>` 不删 `runtime\pythonXXX`：下次重装会跳过运行时复制，省几十秒。
- 记忆数据（`~\.dsh\memory\reme`、`~\.openviking`、`~\.dsh\services\hindsight\profiles`）与安装目录分离，**卸载服务不会删记忆**；要干净迁移，把这三个目录一起搬走 → 装服务包 → 重设 4 个 `LLM_*` → `start.cmd`。
- 插件侧与开关无关：想连插件一起撤，用插件包的 `UNINSTALL.cmd`；两件事互不影响。
