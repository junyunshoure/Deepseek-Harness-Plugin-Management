# v2.0.0 新功能说明（相对 v1.0.0）

> 面向两类读者：**第一次装的人**看「这个功能对我有什么用、怎么点」；**想改的人**看「它落在哪个文件、边界在哪」。
> 每个功能都标了 `位置`，方便你直接翻源码或改配置。

## 0. 一句话总览

v1 是「配置快照 + 手动安装器」；v2 是「装机盘」：空壳机器双击 → 选模式 → 装依赖 → 装插件 → 补配置 → 装技能 → 自检 → 启动，全程无需你手改一个 YAML。同时把本机 6 个自研插件、4 个本地记忆服务、47 篇能力手册、macOS 通道一起纳入。

装了 v2 之后，多出来的东西一共 10 类，下面逐项讲。

---

## 1. 本地自研插件（6 个，v1 完全没有）

v1 的 32 个插件全部来自 npm 或 GitHub；v2 把本机自己写的 6 个也实例化进包。它们以 `link:` 形态装进 profile，实体在 `%LOCALAPPDATA%\DSHPluginsPack\v2.0.0-windows\payload\node_modules\<包名>`（安装时从压缩包复制过去的），改完重启 DSH 生效。

| 插件 | 版本 | 入口 | 作用与边界 |
|---|---|---|---|
| `dsh-feature-profiles` | 0.1.0 | 工具 `feature_profiles` | 按需加载 47 篇能力手册。agent 先看目录，再读需要的那一份，读完才挂载对应工具箱。避免了「一次注入全部手册把上下文吃满」。 |
| `dsh-memory-fusion` | 1.0.0 | 工具 `memory_search` / `reme_search` / `memory_status` | 把 ReMe（个人记忆）与 OpenViking（资料/共享技能）合成一个检索入口，一套会话事件、一份持久捕获日志、双端投递与统一状态。**不是**两个旧插件并列启动，记忆库仍在原位。 |
| `dsh-skill-fusion` | 1.0.2 | 侧边栏「技能」 | 技能融合中心：完整目录、按来源分组、整组开关、GitHub 市场、上游更新检查与逐文件差异预览、统计、诊断、回收站、新建技能向导。取代 v1 的 `dsh-skill-hub` + `dsh-my-skill-manager`。 |
| `dsh-ollama` | 0.1.0 | 侧边栏「Ollama」 | 本地模型管理面板：发现、逐个启用、加载/卸载、拉取/删除、设默认；面板内单次推理并显示速率与选模原因。不接管全局模型配置，不参与 DSH 启动依赖。 |
| `dsh-purge` | 3.0.0 | 技能/指令 | 逆向分析指挥体系（iOS / Android / Windows）：五角色 + 五阶段 + 证据链。 |
| `@local/dsh-client-ui-workbench` | 0.1.0 | 侧边栏「工作台」 | 把 `workbench/` 下的场景、§〇 交接、待办板、派单台账、体检结果读成可点的一面墙；只读，不写文件。 |

**怎么用**：装完启动 DSH，侧边栏会多出「技能 / Ollama / 工作台」三行；`memory_search`、`feature_profiles` 在会话里直接可用（问「有没有关于 XX 的技能」时 agent 会自己调）。

**边界（重要）**：
- 记忆融合生效的前提是 ReMe 或 OpenViking 至少一端在线；都不在线时检索返回 `partial` 并说明原因，不会假装有记忆。
- Ollama 面板不会替你启动 Ollama，也不自动回退云端模型（避免偷偷产生费用）。
- 工作台页面读的是 `%USERPROFILE%\.dsh\workbench`，目录为空时页面是空的，不是故障。

## 2. 安装器三模式菜单（v1 只有一条路）

v1 的行为是「发现目标 profile 已有插件就退出」。v2 改成菜单：

```
[1] 新建模式：目标 profile 必须是干净的，否则中止（最安全，推荐空壳机器）
[2] 补缺模式：只装缺的，已存在的一律不动（在已有环境上叠加）
[3] 备份覆盖：先整份备份，再覆盖依赖与配置（升级/修复用）
```

- 入口：`INSTALL.cmd`（双击）或 `install.ps1 -Mode new|merge|overwrite`。
- 备份位置：`%USERPROFILE%\.dsh\backups\<时间戳>\`，含 `deps-before.json`、`cordis.patch.yml`、`package.json`、`cordis.yml`。
- 全程留痕：`installation-result.json`（包根）+ `%LOCALAPPDATA%\DSHPluginsPack\last-result.json`（跨次记录）。
- 位置：`install.ps1`（外壳、向导、菜单）、`install-helper.cjs`（真正的对接：调官方插件 CLI、写依赖、补配置、装技能）。

## 3. 配置层自动套用（v1 的 `config/` 只能看）

v1 明确写着「安装器不会自动套用配置」。v2 变成**逐条补缺**：

- 只补 `cordis.patch.yml` 里目标 profile 缺失的条目；你已经有的条目一个字都不动。
- 写之前先备份；写完打印「新增 N 条 / 跳过 M 条」。
- 模型接入留成占位符骨架：9 处 `https://YOUR-ENDPOINT.example.com`，你换成自己的中转站地址即可（不改也能用官方模型，只是这些 provider 会连不上）。
- `feature-profiles`（47 篇手册 + always.json）随配置一起复制到 `%USERPROFILE%\.dsh\profiles\desktop\feature-profiles`，插件才读得到。
- 关掉自动套用：`install.ps1 -NoApplyConfig`。

## 4. 本地记忆服务本体包（独立压缩包）

v1 只有插件，插件要连的四个本地服务得用户自己想办法装。v2 把服务本体也打包了：`DSH-Plugins-v2.0.0-Services.zip`（约 2.2 GB 解压后）。

| 服务 | 端口 | 作用 | 数据目录 |
|---|---|---|---|
| ReMe | 2333 | 自动记忆整理（跨会话事实/偏好/决定/待办） | `%USERPROFILE%\.dsh\services\reme` |
| OpenViking | 1933 | 记忆库、资料 URI、共享技能 | `%USERPROFILE%\.dsh\services\openviking` |
| Hindsight | 8888 | 项目知识页 | `%USERPROFILE%\.dsh\services\hindsight` |
| WeKnora | 8080 | 组织知识库 RAG（Linux/Go，跑在 WSL） | `%USERPROFILE%\.dsh\services\weknora` |

- 一键：`SETUP-SERVICES.cmd`（或 `SETUP-SERVICES.ps1 -Only reme,openviking`）。
- 原理：包内带独立 CPython + site-packages 快照，安装时在你机器上现场建 venv，**不复制绝对路径化的 venv**（v1 那种复制法换机必坏）。
- 装完不想要：`stop.cmd` 停掉即可，磁盘占用约 4.3 GB（四个全装）。
- 逐服务细节见 `docs/服务部署指南.md`。

## 5. macOS 通道

`macos/` 下三个脚本：

| 文件 | 用途 |
|---|---|
| `install.command` | 在 Mac 上装插件包。定位 `/Applications/DeepSeek Harness.app`，备份、写配置、装技能、自检。 |
| `build-payload-on-mac.command` | 包里的 payload 是 Windows x64 的二进制依赖，Mac 不能用。这个脚本在 Mac 上按 `migration.json` 的包清单现装一份 mac payload（需要网络）。 |
| `setup-services.command` | 在 Mac 上装四个本地服务（用 uv/pip，不用 Windows 的服务包）。 |

第一次在 Mac 上用，正确顺序是：`build-payload-on-mac.command` → `install.command` →（可选）`setup-services.command`。

## 6. 47 份能力手册（功能档位）

`config/feature-profiles/` 下 47 个 md + `always.json`，一份对应一个插件/系统能力（`context`、`memory`、`deck`、`reverse`、`drawai`、`office`…），由 `dsh-feature-profiles` 插件按需加载。

- 好处：agent 不用一次背下所有工具手册；你说「用 drawio 画个流程」它才去读 `drawai` 那份。
- 你可以自己加：往目录里丢一个带 frontmatter（`id`、`title`、`description`、`when`）的 md，重启即生效。
- 用法细节见 `docs/配置参考.md` 与 `_index.md`。

## 7. 六个技能包

`payload/skills/` 下六个技能，装完落到 `%USERPROFILE%\.dsh\skills\`：

- `hindsight-coding-agent` — 本机 Hindsight 记忆的用法与排障
- `reverse-engineer-anything` — 二进制 / ASAR / Electron 逆向入口
- `cli-anything` — 为 GUI 应用生成 CLI harness
- `cli-hub-meta-skill` — 发现专业软件的 agent-native CLI
- `solidworks-automation` — SolidWorks COM 自动化
- `writing-for-agents` — 写给 agent 看的文档规范

装了技能管理插件时，侧边栏「技能」里能直接看到并按组开关。

## 8. 自检与可机读凭据

| 文件 | 内容 | 什么时候用 |
|---|---|---|
| `VERIFY.cmd` | 逐文件哈希比对 + 条目数比对 + 内核版本比对 | 怀疑包被改坏 / 下载不完整 |
| `DOCTOR.cmd` | 环境体检：内核版本、CLI 入口、依赖完整性、链接是否断、服务端口、配置条目命中数 | 报错时第一步就跑它 |
| `ROLLBACK.cmd` | 回到最近一次备份（`backups\` 里挑） | 装完坏了 |
| `UNINSTALL.cmd` | 摘掉本包装的依赖与链接，保留用户数据与备份 | 彻底不要了 |
| `inventory.json` | 32 依赖 / 6 本地插件 / 6 技能 / 48 手册 / 36 bundle / 256 条目 / 23,249 文件 / 503 MB，含 506 条引用目录记录 | agent 诊断时的对照基准 |
| `checksums.json` | 逐文件 SHA-256 | 校验 |
| `release-validation.json` | 发布前断链检查结果 | 发布者用 |

## 9. AI-agent 适配通道

内核不是 `0.2.1-rc.2`、或者插件报错时，不用自己啃源码：把现场文件丢给你的 DSH agent，让它按 `docs/AI-agent-适配指南.md` 里的清单核对三件事（官方插件 CLI 是否还在、`dsh-app-boot` 的 profile API 是否还在、条目 id 是否还能命中），然后自己改自己验证。指南里有可直接复制的提示词模板。
