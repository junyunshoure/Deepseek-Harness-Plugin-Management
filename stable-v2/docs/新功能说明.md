# v2.1.0 新功能说明（相对 v2.0.0）

> 面向两类读者：**只用不管的人**看「这个功能对我有什么用、怎么点」；**想改的人**看「它落在哪个文件、边界在哪」。
> 每项都标了 `位置`，方便你直接翻源码或改配置。
> 装 v2.1.0 之前应先装过 v2.0.0（或直接用 v2.1.0 全新装）；v1 → v2.1.0 的差异见根 `README.md`。

## 0. 一句话总览

**v2.1.0 的主要增量不是新插件，而是把「补丁要人记命令」变成了默认行为。**

v2.0.0 之后我们发过两份补丁（`v2.0.1-patch.1` 修 ReMe 日志爆盘、`v2.0.2-patch.1` 做七项环境维护）。补丁的问题是：**它得你自己记得去装、记得按顺序跑、记得看输出**。v2.1.0 把这些动作折进包里，装完就在，`MAINTAIN.cmd` 一个入口。

同时做了两件配套的事：

- **升级路径闭环**：v2.0.x → v2.1.0 用 D 模式一条命令，逐条 `realpath` 核对（这是原来最容易翻车的地方：载荷落点带版本号，升级后 6 个自研插件会静默失效）。
- **payload 瘦身 36.6%**：502.41 MB → 318.79 MB，一个字节的运行依赖都没少。

一共 11 项，逐项讲。

## 1. 升级模式 D（`UPGRADE.cmd`）

**对你有用在哪**：装过 v2.0.0 的人不用再记命令、不用手改 `package.json`、不会出现"升级完 6 个自研插件没了"。

**怎么用**：解压新包 → 双击 `UPGRADE.cmd`（= `install.ps1 -Action upgrade`）→ 等它跑完。

它做的事：

1. 按 `checksums.json` 逐文件校验新包。
2. 把载荷复制到 `%LOCALAPPDATA%\DSHPluginsPack\v2.1.0-windows\`（旧载荷 `v2.0.0-windows` 原样保留）。
3. 读出 profile 里现有的 32 条 `link:<绝对路径>` → 备份 → 逐条重指向新载荷。
4. **逐条 `fs.realpathSync` 核对**：profile 的 `node_modules/<包名>` 解引用后必须正好落在新载荷里，任何一条不对就 `die`。
5. 断言 `dsh.profile.bundles` 里含全部目标，打印「重指向核对通过：33 个插件」。

**实测证据**（走的是真实升级路径：32 条依赖全是 `link:` 指向旧载荷）：

```
✓ SHA-256 完整性校验通过：10745 个文件
安装模式：D 升级
✓ 重指向核对通过：33 个插件全部指到 ...\DSHPluginsPack\v2.1.0-windows\payload\node_modules
✓ 本次重定向 32 个
✓ 插件组合校验通过：256 个条目，37 个 bundle
```

二次执行幂等（技能走"已存在→备份→覆盖"，`技能：0 个新增`）。升级后 `dsh --profile <副本> --dump-config` → exit 0、1,906 行、`skipping profile bundle` = **0**。

**边界**：

- 不做"覆盖配置"。配置仍按逐条补缺；你已有的条目一字不动。
- 不做"卸载旧载荷"。想腾空间用 `PRUNE.cmd`（见第 6 项）。
- 如果 profile 里有 **git 依赖**（比如 `treg-dsh` 这类 `codeload.github.com/...tar.gz`），那个包可能挂不上，会记成"告警"而不是失败（见第 9 项）。

**位置**：`install.ps1`（`-Action upgrade` 分支）、`install-helper.cjs`（`mode === 'upgrade'` 的挂载语义与收尾断言）。

## 2. 修复模式 E（`-Action repair`）

**对你有用在哪**：插件"装过但不见了"——载荷目录被删、盘符变了、手滑删了 `%LOCALAPPDATA%` —— 一条命令重挂回来，不碰别的。

**为什么需要它**：DSH 遇到断链的 `link:` 是**静默跳过**（日志一行 `dsh: skipping profile bundle "..."`，`--dump-config` 仍 exit 0）。所以"插件消失"在界面上表现为"什么错都没有，就是少了几行"。这是 v2.1.0 最需要人知道的一条。

**怎么用**：先 `DOCTOR.cmd` 看"link: 目标全部存在"，不通过就 `install.ps1 -Action repair`（或 `install.ps1 -Action install` 选 E）。

**与 D 的区别**：D 会重指向到新载荷；E 只重挂本包已声明的插件，不新增、不动版本、不动配置。

**位置**：`install.ps1`（菜单 E）、`install-helper.cjs`（`repair` 不新增未声明依赖）。

## 3. 维护引擎 `MAINTAIN.cmd` / `maintain.ps1`

**对你有用在哪**：两份补丁的七项动作（CL-001…CL-007）现在装完就能跑，一条命令，带备份和回滚。

**怎么用**：

```powershell
.\MAINTAIN.cmd                    # 8 步，改文件的步骤都会先备份
.\MAINTAIN.cmd -CheckOnly         # 只看不改（实测：真机一行未动）
.\MAINTAIN.cmd -Rollback          # 按 manifest 逐文件还原
.\MAINTAIN.cmd -NoAppendix        # 不动 AGENTS.md
```

8 步：

| 步 | 动作 | 幂等性 |
|---|---|---|
| 1 | 包自检（按 `checksums.json` 逐文件 SHA-256） | — |
| 2 | 定位 `~/.dsh` 与所有 profile | — |
| 3 | **AGENTS 附录块**（替换式写入，写完断言标记各 1 个） | 是 |
| 4 | CL-001 ReMe 日志轮转 `00:00` → `100 MB` | 是（已是体积轮转跳过） |
| 5 | CL-002/003 废弃包残留 + CL-004 空 bundle 目录 | 是 |
| 6 | CL-005 `*.tmp` 残留 | 是 |
| 7 | CL-006 超过 100 MB 的日志目录巡检（v2.1.0 新增） | 只报不改 |
| 8 | CL-007 四个 `LLM_*` 用户变量检查 | 只报不改 |

**边界**：

- 备份落在 `%LOCALAPPDATA%\DSHPluginMigration\maintenance-20261029\backup-<时间戳>\`，`manifest.json` 记录每个被改文件的原哈希；`removedDirs` 记录被删目录（回滚时重建）。
- CL-001 改完要**重启 ReMe** 才生效。
- CL-007 发现缺变量时，可以用 `maintain.ps1 -LlmBaseUrl <url> -LlmModel <name> -LlmApiKey <key>` 让它代写（不传就只提示）。
- 它不碰 `cordis.patch.yml`，不装插件，不启 GUI。

**位置**：`maintain.ps1`（28,041 B，8 步），入口 `MAINTAIN.cmd`。

## 4. 对齐协议附录（`appendix/AGENTS.appendix.md`）

**对你有用在哪**：让你的 agent 在动手前先把方案对齐（问题清单 + 推荐默认值 + 难度分级），而不是闷头干。

**怎么用**：`MAINTAIN.cmd`（第 3 步）会把它写进 `~/.dsh/AGENTS.md`。也可以手工 `cat appendix/AGENTS.appendix.md >> ~/.dsh/AGENTS.md`（但**别重复追加**，见边界）。

**它写什么**：ALIGNMENT_PROTOCOL v1.0 全 9 节——难度分级 D0–D3 与对应问题数、执行参数用交互卡片单独问、方案问题走编号清单（每问带推荐默认值与取舍）、一轮收束、不触发白名单、与深度档位合并、执行后的对齐回执、子代理派发要求、反例。

**边界（重要）**：写法是**替换式**——找到 `<!-- ALIGNMENT_PROTOCOL v1.0 START ... -->` 到 `<!-- ALIGNMENT_PROTOCOL v1.0 END -->` 这一对标记，整段换掉，绝不追加。

- 检测到 **2 个以上** 标记块时它**拒绝自动处理**并提示你手工清到一对（删错段落会丢你自己的规则）。
- 写完自己断言"START 1 个 / END 1 个"，不达标就报错并指向 `-Rollback`。
- 只数**行首**标记，正文里提到标记不会被误算。

**位置**：`appendix/AGENTS.appendix.md`（4,806 B）、`maintain.ps1` 第 3 步。

## 5. 场景记忆工具箱（`templates/workbench-toolkit/`）

**对你有用在哪**：给"多场景工作台"配套的那套脚本与规格（场景登记、交接、发消息、例外清单）。

**怎么用**：**它不会自动落盘**。因为它只对"工作台目录"有意义，而每个人的工作台路径不同。装完自己拷：

```powershell
# 示例：拷到你的工作台目录
Copy-Item -Recurse "<包目录>\templates\workbench-toolkit\*" "D:\你的工作台\"
```

验收：


**7 个文件**：

| 文件 | 大小 | 作用 |

| `scripts/场景记忆.mjs` | 44,191 B | 场景登记 / 交接 / 体检 / 迁移 |
| `scripts/发消息.mjs` | 4,250 B | 向某个场景投一条消息 |

## 6. 旧载荷清理（`PRUNE.cmd` / `--prune-old`）

**对你有用在哪**：升级后旧载荷（`v2.0.0-windows`）还占着几百 MB，想腾空间。

**怎么用**：

```powershell
.\PRUNE.cmd                                  # 预演：打印会删什么、保留什么
.\PRUNE.cmd -KeepDays 3                     # 缩短保留期
.\install-helper.cjs --prune-old --yes      # 真删（默认保留 7 天）
```

**三条规则**：

1. 默认**保留 7 天内**的载荷（`--keep-days N` 可改）。
2. **仍被任何 profile 的 `link:` 引用的目录永不删**——删了就是断链（第 2 项那个坑）。
3. 不带 `--yes` 只预演。

`UNINSTALL.cmd` 删载荷前同样先查引用。

**位置**：`install-helper.cjs` 的 `pruneOldStores(spec)` / `listStores()`。

## 7. payload 瘦身 −36.6%（502.41 MB → 318.79 MB）

**对你有用在哪**：下载小 36.6%，解压后占盘小 183 MB，装得更快。**一个运行依赖都没少**。

怎么做到的（三层，全部有实测断言）：

| 层 | 做法 | 省下 |
|---|---|---|
| 1 | `dsh-skill-fusion` 只带 **runtime 依赖**（`js-yaml`），不带 5,047 个 devDependencies 文件 | 91.8 MB → 3.0 MB（−88.6 MB） |
| 2 | 全局白名单：`tests / test / examples / .github / coverage / benchmark / *.map / tsconfig* / CHANGELOG.md` 等在**复制时**就过滤掉 | 1,101 个文件 / 18.10 MB |
| 3 | 剩下 5 个自研插件本来就没有自己的 `node_modules`（`memory-fusion` 目录里那 397 MB 其实是被 `link:` 带进来的**整个 profile 镜像**，不是它的依赖） | 不计入 |

关键判断依据：

- **peer 依赖由内核提供**。`appendix` 里那 15 条 `@deepseek-ai/*` peer 不需要插件本地带 `node_modules`——`dsh-feature-profiles` 插件（0 文件 `node_modules`）当前就在正常运行，这是铁证。
- **不能删 `.pnpm` 了事**。`node_modules/js-yaml` 是 Junction（`LinkType=Junction` → `.pnpm/js-yaml@4.1.1/...`），直接删 `.pnpm` 必断链。所以裁剪走"解引用实体复制"（`fs.cpSync(..., { dereference: true })`），实测裁完 `isSymlink=false`。
- **不做 `pnpm install --prod` 重装**。会引入联网与重装风险，而静态度量已证明没必要（全 payload 只有 1 个包、0.06 MB 属于可裁的 devDependency）。

**怎么验证没裁坏**：裁剪版与原版的 host 入口逐字段比对 `diffCount: 0`；在 throwaway profile 里 `--dump-config` **字节数完全相同**（12,079 B），`skipping profile bundle` = 0。

**位置**：装配器 `assemble.mjs` 的 `LINK_MAP[].runtime`（只有 skill-fusion 是 `['js-yaml']`）与 `DROP_DIRS` / `DROP_FILE_RES`；inventory 的 `trimmed` 段记录裁了哪些、多少。

## 8. 内核门禁：只提示不阻断

**对你有用在哪**：内核 `0.3.x` 的人不用再靠 `-ForceKernel` 硬装。

- `migration.json` 的 `kernel.required`：`>=0.2.0 <0.3.0` → **`>=0.2.0 <0.4.0`**。
- `0.2.x` / `0.3.x` 都放行；与本包构建基准（`0.2.1-rc.2`）不同**只打印一行提示**。
- `>=0.4.0` 或 `<0.2.0` 仍要 `-ForceKernel`。

**边界**：0.3.x **只是放行，没有实机验证**。真要适配，看 `docs/AI-agent-适配指南.md`。

**位置**：`migration.json`、`install.ps1` 的内核检查段、`install-helper.cjs --check-only` 的门禁文案。

## 9. 离线优先：默认不偷偷联网

**对你有用在哪**：装机不再"卡在一个网络请求上等超时"，也不会在你不知情的情况下把几百个包从 npm 拉下来。

**行为**：挂载某个包失败时按三级回退——

1. `dsh plugin add <pkg> --offline`
2. `dsh plugin add <pkg> --offline --config.lockfile=false`（实测 771–845 ms、exit 0、不联网）
3. 仍失败 → **默认不联网**，记入 `warned[]` 继续装完，最后汇总打印三条补挂办法

**为什么要这么设计**：根因是 profile 里可能有 **git 依赖**（`treg-dsh` 那条 `codeload.github.com/superdesigndev/treg/tar.gz/...`）。pnpm 解析整张依赖图时，会因为一个 tarball 不在离线 store 而把**同批的 link 包也连带判失败**。旧的"离线失败就联网重试"会把 200+ 实体包装进 profile，破坏"全部插件 `link:` 到载荷"的离线语义——升级就不再可回滚了。

**要联网怎么办**：显式加 `-AllowNetwork`（或 `install-helper.cjs --allow-network`）。

**模式差异**：`new / merge / backup`（安装类）里 `warned` 并入 `failed`（必须全绿）；`upgrade / repair` 只告警不中断。

**位置**：`install-helper.cjs` 的 `offline-fallback` 与 `warned-handling` 段。

## 10. `--skills-root`：让演练不碰真身

**对你有用在哪**：想试装、想跑测试、想给别人演示，又不想动自己 `~/.dsh/skills` 与 `~/.agents/skills`。

```powershell
.\install.ps1 -SkillsRoot "D:\tmp\skills-drill"
# 技能会落到 D:\tmp\skills-drill\dsh\ 与 D:\tmp\skills-drill\agents\
```

**顺带修的一个坑**：Electron 子进程下 `mkdir ~/.agents/skills/<技能名>` 偶发 `EPERM`，以前会让整个安装失败。现在每个技能 `try/catch` + 3 次重试（300/600/900 ms 退避），仍失败只告警。

**位置**：`install.ps1`（`-SkillsRoot`）、`install-helper.cjs`（`skTargets` 与 `skills-robust`）。

## 11. 体检强化与文档补齐

**`DOCTOR.cmd` 新增三项检查**：

1. **profile 里所有 `link:` 目标是否存在**（断链会静默跳过插件，这是"插件消失"的唯一可查证据）。
2. **持久目录里有多个载荷版本**时提示（升级后同时有 `v2.0.0-windows` 与 `v2.1.0-windows` 是正常的，但值得知道）。
3. **日志目录 > 100 MB** 巡检（`profiles\*\logs` 与 `~/.dsh/logs`）。

**文档**：根 `README.md` 按 v2.1.0 重写（含 A–E 五模式表、11 项新增、出问题对照表）；`CHANGELOG.md` 逐条列新增 10 / 变更 10 / 修复 5 与验证证据；`docs/使用说明书.md` 新增 §10.2 / 10.2b / 10.2c / 10.2d 四节；`docs/常见问题.md` 新增"v2.1.0 新增问题"五节；`docs/配置参考.md` 补内核门禁说明。

**位置**：`install-helper.cjs` 的 doctor 段、各文档。
