# DeepSeek Harness 插件整合包 v2.1.0（Windows）配置参考

这份手册只讲四件事：配置分几层、每个文件归谁管、模型怎么接、改坏了怎么退。
安装流程看 [使用说明书](使用说明书.md)，报错排查看 [常见问题](常见问题.md)。

**路径记号**（全文通用）：

| 记号 | 实际位置 |
| --- | --- |
| `<profile>` | `%USERPROFILE%\.dsh\profiles\desktop` |
| `<home>` | `%USERPROFILE%\.dsh` |
| `<store>` | `%LOCALAPPDATA%\DSHPluginsPack\v2.0.0-windows`（安装器持久目录） |

## 1. 配置分三层

| 层 | 位置 | 谁维护 | 你能改吗 | 管什么 |
| --- | --- | --- | --- | --- |
| ① 内核层 | `<desktop>\resources\app.asar\dsh` | 官方安装包 | 不改 | 内核本体 + 4 个内置 bundle（`@deepseek-ai/dsh-base`、`dsh-web-app`、`dsh-experimental-agent-team-profile`、`dsh-experimental-auto-review`） |
| ② profile 层 | `<profile>\package.json` 的 `dsh.profile.bundles`（36 项）+ 每个 bundle 自带的 patch | 官方 CLI / `pnpm` / 安装器 | 半可改（见第 2 节） | 装哪些插件、每个插件的默认配置 |
| ③ 用户 patch 层 | `<profile>\cordis.patch.yml` | 你 | 随便改 | 按 id 定向覆盖：启停、`config`、`env`、`insert` |

合成顺序（有据可查，不是猜的）：

1. `cordis.yml` 第 1–3 行注释写明：先 `package.json` 里 `dsh.profile.bundles` 的每个 bundle，再 `cordis.patch.yml`，最后是命令行 `--patch` 覆盖层。
2. `cordis.patch.yml` 第 14–16 行：本层「applied after every bundle layer」，是一个 id 定向的 patch 数组（可用 `!!js` 表达式）。
3. `install-helper.cjs` 第 606–608 行校验时也是这么排的：`composeEntries([...composed.layers.map(l => l.patches), composed.patches])` —— bundle 层在前，profile 的 patch 在最后。

### 为什么「改 cordis.patch.yml 而不是 cordis.yml」

`<profile>\cordis.yml` 全文就 4 行，根节点是个空数组：

```yaml
# dsh profile root — an empty entry list. The tree is composed as patches:
# each bundle in package.json's dsh.profile.bundles, then cordis.patch.yml, then any
# --patch overlays. Edit cordis.patch.yml, not this file.
[]
```

插件树不是写在这里的，而是「`package.json` 的 bundle 清单 + 各 bundle 的 patch + 你的 `cordis.patch.yml`」现场组合出来的。往 `cordis.yml` 里手写条目等于绕过 bundles 链，重装或升级插件时会被覆盖，也可能让 GUI 的插件管理看不到真实来源。**要改配置，一律改 `cordis.patch.yml`。**

### home 级 patch 是第三块补丁

`<home>\cordis.patch.yml` 是跨 profile 的全局补丁层。本机现在长这样（32 行，根仍是空数组）：

```yaml
# 1–16 行注释：2026-10-22 为修「会话秒失败」临时禁用 rea-mcp（它注册 207 个工具，
#              schema 774,808 字节 ≈ 193,702 tokens，直接触发 413 preflight_compress_failed）
# 18–30 行是整段被注释掉的 - insert:（id: rea-mcp，MCP client 条目），去掉 "# " 即可恢复
[]
```

用法约定：

- 只想「全局临时关掉/塞进一个条目」→ 写这里，别动 profile。
- 想改模型、provider、默认模型、插件 config → 写 `<profile>\cordis.patch.yml`。
- **同一个 id 不要在两处都写**，否则排查时你会不知道哪一层生效。

### v2.1.0 变更：内核门禁从"硬拒"改成"只提示"

`migration.json` 里的 `kernel.required` 已从 `>=0.2.0 <0.3.0` 放宽到 **`>=0.2.0 <0.4.0`**：

| 你的内核 | v2.0.0 行为 | v2.1.0 行为 |
|---|---|---|
| `0.2.x`（本包构建基准 `0.2.1-rc.2`） | 装 | 装 |
| `0.3.x` | 拒绝（需 `-ForceKernel`） | **装，只打印一行提示** |
| `>=0.4.0` 或 `<0.2.0` | 拒绝 | 拒绝（仍要 `-ForceKernel` 才硬装） |

配套字段：`migration.json` 的 `supportedModes` 现在列出 `new / merge / backup / upgrade / repair` 五种；`storeLayout` 说明载荷落在 `%LOCALAPPDATA%\DSHPluginsPack\v<version>-windows`。

想做 0.3.x 的适配工作，看 [`AI-agent-适配指南.md`](AI-agent-适配指南.md)。

## 2. 每个文件一张表

| 文件 | 谁写 | 能手改 | 改完要重启 | 装错怎么恢复 |
| --- | --- | --- | --- | --- |
| `<profile>\cordis.yml` | 安装器首次拷贝样本；平时由内核维护 | 不建议（根保持 `[]`） | 是 | 从 `config\cordis.yml` 复制回来；或 `ROLLBACK.cmd` |
| `<profile>\cordis.patch.yml` | 你 + 安装器（首次拷贝；已存在时只**追加缺失条目**） | **主要改这里** | 是（完全退出 App 或 `Ctrl+R`） | 同目录 `.before` / `.bak-*` 文件；或跑 `ROLLBACK.cmd` |
| `<profile>\package.json` | 官方 CLI（`plugin add`）+ `boot.writeProfileBundles` | 仅 `dsh.profile.bundles` 增删；`link:` 路径别手改 | 是 | `ROLLBACK.cmd`（依赖回到 `deps-before.json`，并删掉本包新增的包） |
| `<profile>\pnpm-workspace.yaml` | 安装器拷贝样本；`pnpm` 读取 | 不建议（hoisted / allowBuilds / minimumReleaseAgeExclude 是配套的） | 否（下次 pnpm 操作生效） | 从 `config\pnpm-workspace.yaml` 复制回来 |
| `<profile>\pnpm-lock.yaml` | `pnpm` 自动生成 | 不要手改 | 否 | 删掉让 pnpm 重算，或从备份恢复 |
| `<home>\.credentials.yaml` | GUI「设置 → 模型」写入 | 可（结构见 3.3），**绝不外传** | 否（下次请求生效） | 重填密钥；此文件不在备份里，自己留底 |
| `<home>\cordis.patch.yml` | 你 | 可（home 级补丁） | 是 | 旁边有 `.bak-*`；只需保证根 `[]` 合法 |
| `<profile>\feature-profiles\*` | 安装器 `copyTree`（已存在则不覆盖） | 可，且改了只影响「给 agent 的手册文字」 | 否（下次加载生效） | 从 `config\feature-profiles` 重新复制单份 |

三条 installer 的实际行为（`install-helper.cjs`）：

- 第 364 行 `KERNEL_OWNED = ['package.json','pnpm-lock.yaml','pnpm-workspace.yaml']` —— 这三个**永远不会**被包内样本覆盖，安装器只通过官方 CLI 动它们。
- 第 369–382 行：`cordis.patch.yml` 不存在就整份拷贝；存在则先备份成 `<backup>\cordis.patch.yml.before`，再**按 id 追加**包里有、你没有的条目，追加段带注释 `# === 以下条目由插件整合包 v2.0.0 追加（你的原有条目一条没动） ===`。
- 第 387–394 行：其余配置文件若目标已存在，样本另存为 `<profile>\<文件名>.pack-sample`，不覆盖你的。

## 3. 模型接入怎么填

所有模型配置都在 `<profile>\cordis.patch.yml`。包里样本的对应位置：

| 条目 | 行号（`config\cordis.patch.yml`） | 内容 |
| --- | --- | --- |
| `llm-pi-ai` | 50–163 | 7 个 provider：`openai` / `anthropic` / `anthropicmini` / `google` / `grok` / `openai-guankey` / `deepseekzhongzhuan` |
| `llm-deepseek` | 164–177 | 官方 DeepSeek 直连（`retryPolicy` + `models: []`） |
| `agent-default-model` | 198–203 | 默认用哪个 provider / model / 推理强度 |

### 3.1 三种典型接法

**A. 只用官方 DeepSeek**（不接中转站）

删掉 50–163 行整段 `- id: llm-pi-ai`，保留 `llm-deepseek`，把它的 `baseURL`（第 167 行）换成官方地址：

```powershell
$f = "$env:USERPROFILE\.dsh\profiles\desktop\cordis.patch.yml"
$l = Get-Content $f -Encoding utf8
($l[0..48] + $l[163..($l.Count - 1)]) | Set-Content $f -Encoding utf8   # 删掉 50–163 行
# 之后手改剩下的 llm-deepseek 段：baseURL 换成官方地址，models: [] 保持不动
(Select-String -Path $f -Pattern 'llm-pi-ai').Count                          # 期望 0
```

删完后 `llm-deepseek` 的 `baseURL` 落在第 53 行附近（原 167 行减去被删的 114 行）。密钥沿用 `DEEPSEEK_API_KEY`。

**B. 中转站**（包里默认形态）

把 8 个 `baseURL` 的 `https://YOUR-ENDPOINT.example.com` 全换成中转站地址（第 55/94/108/119/132/149/160/167 行；第 4 行是注释里的同一个字符串，一并换掉更整齐）：

```powershell
$f = "$env:USERPROFILE\.dsh\profiles\desktop\cordis.patch.yml"
(Get-Content $f -Raw -Encoding utf8) -replace 'https://YOUR-ENDPOINT\.example\.com', 'https://relay.example.com' |
  Set-Content $f -Encoding utf8
(Select-String -Path $f -Pattern 'YOUR-ENDPOINT').Count   # 期望 0
```

注意：只换地址不换模型名。中转站里模型 id 若和 `gpt-5.6-sol` 这类名字不一致，就按中转站的清单改 `models[].id`（`name` 只影响界面显示）。

**C. 多 provider 混用**

在 `providers:` 下再加一段即可（示例键名 `myrelay`，位置随意，放 `openai` 前后都行）：

```yaml
      myrelay:
        displayName: 我的中转
        apiKeyEnv: MYRELAY_API_KEY
        api: openai-completions
        baseURL: https://relay.example.com
        models:
          - id: deepseek-v4.1-flash
            name: DeepSeek V4.1 Flash
            contextWindow: 128000
            maxTokens: 8192
            input:
              - text
```

然后在 `<home>\.credentials.yaml` 的 `refs:` 下加同名键 `MYRELAY_API_KEY: sk-xxxx`（或在 GUI 里填），最后把默认模型指过去（见 3.4）。

### 3.2 provider 字段逐项解释

| 字段 | 必填 | 含义 | 坑 |
| --- | --- | --- | --- |
| 键名（如 `openai`） | 是 | provider 的内部 id，`agent-default-model` 的 `provider` 就写这个 | 改键名等于换了个 provider，默认模型要跟着改 |
| `displayName` | 否 | GUI「设置 → 模型」里显示的名字 | 仅显示用，不影响请求 |
| `baseURL` | 是 | 接口根地址（不含 `/chat/completions`） | 占位符没换 = 直接连不上，最常见故障 |
| `apiKeyEnv` | 是 | 读密钥用的**变量名**，不是密钥本身 | 必须和 `.credentials.yaml` 的 `refs` 键名逐字一致 |
| `api` | 视插件 | 协议形态：`openai-completions` 或 `anthropic-messages` | 中转站给的是 OpenAI 兼容接口却填 `anthropic-messages`，会 400/404 |
| `models[].id` | 是 | 真实模型名，发给服务端的就是它 | 必须与中转站清单一致，写错报「模型不存在」 |
| `models[].name` | 否 | 界面显示名 | 随便写 |
| `models[].contextWindow` | 建议 | 上下文窗口（token） | 写大了会被服务端截断，写小了压缩策略偏保守 |
| `models[].maxTokens` | 建议 | 单次最大输出 | 超过服务端上限会报参数错误 |
| `models[].input` | 否 | 模态：`text` / `image` | 不支持图片的模型别写 `image`，否则发图会报错 |

### 3.3 密钥写哪里（优先级与坑）

| 写法 | 位置 | 优先级 | 说明 |
| --- | --- | --- | --- |
| GUI 填写 | 设置 → 模型 → 对应 provider | 写入 `.credentials.yaml` 的 `refs` | 最省事，推荐 |
| `.credentials.yaml` 手写 | `<home>\.credentials.yaml` → `refs:` | 同上，等价 | 结构：`version: 1` + `records:`（账号/浏览器会话）+ `refs:`（密钥） |
| 环境变量 | 系统/用户环境变量 | 作为兜底解析 | `apiKeyEnv` 指向的名字能在环境里找到也行 |

本机 `refs:` 下已有 9 个键名（值不在本文档出现）：`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`ANTHROPICMINI_API_KEY`、`DEEPSEEK_API_KEY`、`GOOGLE_API_KEY`、`GROK_API_KEY`、`OPENAI_GUANKEY_API_KEY`、`DEEPSEEKZHONGZHUAN_API_KEY`、`DSH_WEIXIN_BOT_TOKEN_5196C76495A2E49EC70E8E8F`。

**最常见的坑**：`apiKeyEnv: OPENAI_API_KEY` 而 `refs` 里写的是 `OPENAI_KEY` —— 名字差一个字符就当作「没配密钥」，界面表现为「模型列表空 / 调不通」。改键名后必须同时改 `apiKeyEnv`。

### 3.4 默认模型

`config\cordis.patch.yml` 第 198–203 行：

```yaml
- id: agent-default-model
  name: "@deepseek-ai/dsh-agent-default-model"
  config:
    provider: deepseek-account     # 换成你 provider 的键名，如 openai / myrelay
    model: deepseek-flash          # 该 provider 下 models[].id
    reasoningEffort: high          # 推理强度：整合包用 high；想更快更省可降
```

三层一起对：`provider` 有定义 → 该 provider 的 `models` 里有这个 `id` → `apiKeyEnv` 有真密钥。三者缺一，发送时才会报错。

## 4. 启停条目

patch 数组里每一项就是一个条目，能写的字段：

| 字段 | 作用 | 示例 |
| --- | --- | --- |
| `- id: <条目 id>` | 定位到哪个条目（必写） | `- id: tool-bash` |
| `name:` | 覆盖包名，用于第三方插件注册的「子入口」 | `name: "@vectorize-io/hindsight-coding-agents/dsh"` |
| `disabled: true/false` | 停用 / 启用 | `- id: web-ui-ssh` + `disabled: false` |
| `config:` | 深度覆盖插件配置（只覆盖你写到的字段） | 见 40–47 行 `web-ui-pet` |
| `env:` | 给插件进程注入环境变量 | 见 195–196 行 |
| `- insert:` | 往树里**新增**条目（不是覆盖） | 见 `<home>\cordis.patch.yml` 18–30 行注释块 |

现成片段（`config\cordis.patch.yml`）：

```yaml
# 178–189 行：工具面
- id: tool-bash
  disabled: true
- id: tool-pwsh
  disabled: false
- id: bash-sandbox
  disabled: true

# 193–197 行：第三方插件的子入口 + env 注入（注意 "5" 要加引号）
- id: hindsight
  name: "@vectorize-io/hindsight-coding-agents/dsh"
  env:
    HINDSIGHT_PAGE_REFRESH_EVERY_TURNS: "5"
  disabled: false

# 40–47 行：config 覆盖（只改列出的键，其余保持 bundle 默认）
- id: web-ui-pet
  name: "@linxin666/dsh-pet"
  config:
    visible: true
    size: 160
```

写法要点：

- 一个条目里 `id` 必须在 bundle 层或本层存在，否则这一项被忽略（日志里会出现「被跳过的 bundle/条目」提示）；`disabled` 不要写成带引号的 `"true"`，YAML 会当字符串，个别插件按假值处理。
- 想彻底停掉一类工具：工具和它的沙箱要一起停（`tool-bash` + `bash-sandbox`）。整合包样本就是这么成对写的。

## 5. 占位符清单

| 占位符 / 值 | 出现位置 | 含义 | 换成什么 | 必须换？ |
| --- | --- | --- | --- | --- |
| `https://YOUR-ENDPOINT.example.com` | `config\cordis.patch.yml` 第 55/94/108/119/132/149/160/167 行 | 各 provider 的接口根地址 | 你的中转站或官方地址 | **是**，8 处全换，否则一个模型都调不通 |
| 同上 | `config\cordis.patch.yml` 第 4 行 | 顶部注释里的示例 | 可留（纯注释） | 否 |
| 同上 | `docs\常见问题.md`（4 处） | 文档示例 | 不用动 | 否 |
| `apiKeyEnv: *_API_KEY` | 各 provider | 密钥的**变量名** | 换中转站不必改；自己换键名时两处同步 | 否 |
| `petId: whale-girl-refined` | 第 47 行 | 桌面宠物形象 | 想换形象再改 | 否 |
| `right: 267` / `bottom: 1039` | 第 45–46 行 | 宠物像素坐标 | 按屏幕自己调 | 否 |
| `provider: deepseek-account` / `model: deepseek-flash` | 第 201–202 行 | 默认模型 | 换成你实际可用的 provider/model | 接中转站后**建议换** |

判断标准很简单：**跑完安装若「设置 → 模型」里点任何一个模型都报错，先数 `YOUR-ENDPOINT` 是否还剩 8 个。**

## 6. 几道常见改法

改完都要**完全退出 App 再打开**（或 `Ctrl+R` 刷新页面）才生效。

### 6.1 换中转站

- 改：`<profile>\cordis.patch.yml` 的 8 个 `baseURL`（见 3.1 B 的命令）。
- 验证：`(Select-String -Path $f -Pattern 'YOUR-ENDPOINT').Count` 为 0；GUI 里发一句「hi」，看是否正常回。

### 6.2 加一个模型

- 改：找到对应 provider 的 `models:`，照格式加一项（`id` 必填，`name`/`contextWindow`/`maxTokens`/`input` 建议填）。
- 验证：重启后「设置 → 模型」里能看到新名字并选中发一句；报「模型不存在」说明 `id` 和服务端不一致。

### 6.3 关掉某个插件

- 改：文件末尾加两项即可（同名 id 以你写的为准）：

```yaml
- id: dsh-cost-meter
  disabled: true
```

- 验证：`DOCTOR.cmd` 里「插件条目组合」仍应报告条目数（整合包基线 256 个），`disabled: true` 只停用不删除；界面侧边栏对应入口消失即生效。

### 6.4 把 bash 工具换回 pwsh

- 改：第 178–189 行这段，反过来写：

```yaml
- id: tool-bash
  disabled: false
- id: tool-pwsh
  disabled: true
- id: bash-sandbox
  disabled: false
```

- 验证：重启后让 agent 跑一条 `Get-Location`，返回 `D:\...` 说明走的是 pwsh；两个都开也能用，但同名命令会被其中一个先接管，容易看日志看花眼。

### 6.5 让 hindsight 每 5 轮才刷新

- 改：第 193–197 行的 `env`，值必须是带引号的字符串：

```yaml
- id: hindsight
  name: "@vectorize-io/hindsight-coding-agents/dsh"
  env:
    HINDSIGHT_PAGE_REFRESH_EVERY_TURNS: "5"
```

- 验证：连开 5 轮以上对话，工具指南不再每轮重发（每轮约省 3.2 KB）；想立刻恢复就改回 `"1"`。

### 6.6 改默认模型

- 改：第 198–203 行 `agent-default-model` 的 `provider` / `model` / `reasoningEffort`。
- 验证：重启后新会话顶部显示的模型名变了；发一句长任务看是否按 `reasoningEffort` 表现。

## 7. 验证与回滚

| 命令 | 实际做什么 | 看什么 |
| --- | --- | --- |
| `VERIFY.cmd` | `install.ps1 -Action verify` → `install-helper.cjs --check-only`：按 `checksums.json` 逐文件比对 SHA-256，再确认内核版本 | `✓ SHA-256 完整性校验通过：N 个文件` / `缺少文件（包可能没有完整解压…）` / `文件内容与校验清单不符（下载或解压损坏）` |
| `DOCTOR.cmd` | `--doctor`：找 Desktop 目录、内核版本 vs `>=0.2.0 <0.3.0`、profile 是否存在、bundle/依赖计数、插件条目组合、GUI 端口、记忆服务端口（ReMe 2333 / OpenViking 1933 / Hindsight 8888 / WeKnora 8080）、可回滚备份数量 | `插件条目组合：256 个` 是整合包基线；`✗` 行是阻塞项 |
| `ROLLBACK.cmd` | `--rollback`：取 `<store>\backups` 里最新且含 `deps-before.json` 的备份，还原配置、依赖、bundle 列表、技能 | `✓ 已还原配置 / ✓ 已移除本包依赖 / ✓ bundle 列表已回到 N 个` |
| `UNINSTALL.cmd` | `--uninstall`：先做一份 `uninstall-<时间戳>` 备份，再移除本包挂载 | 卸载后想反悔，仍可用那份备份 |
| `SETUP-SERVICES.cmd` | `--services-only`：装 ReMe / OpenViking / Hindsight / WeKnora 本体 | 只在你要用本地记忆服务时需要 |

结果文件：`<store>\installation-result.json`（完整步骤与备份路径），另外 `%LOCALAPPDATA%\DSHPluginsPack\last-result.json` 记录最近一次动作。

### `.pack-sample` 是什么

`install-helper.cjs` 第 384–394 行：`config\` 下除 `cordis.patch.yml`、`feature-profiles`、以及三个内核文件（`package.json` / `pnpm-lock.yaml` / `pnpm-workspace.yaml`）之外的每个文件，若你在 profile 里已经有同名文件，安装器**不覆盖**，而是把包里的样本另存为 `<profile>\<文件名>.pack-sample`。

它只是「参考样本」：想用包里的版本，就对比后手工覆盖；想保留自己的，就别动它。v2.0.0 的 `config\` 只有 4 个文件加 `feature-profiles`，所以正常安装通常不会生出 `.pack-sample`，看到它说明目标位置已存在同名文件。

### `backups\<时间戳>` 里有什么

位置：`<store>\backups\<时间戳>`（`stamp()` 形如 `2026-10-28T20-35-21`）。安装前备份（`install-helper.cjs` 第 270–279 行）与卸载备份（第 713 行 `uninstall-<时间戳>`）结构一致：

| 内容 | 说明 |
| --- | --- |
| `package.json` | 安装前的 profile 清单（依赖 + bundles） |
| `pnpm-lock.yaml` / `pnpm-workspace.yaml` | 安装前的包管理与工作区设置 |
| `cordis.yml` / `cordis.patch.yml` | 安装前的配置文件 |
| `deps-before.json` | 快照：`{ at, mode, dependencies, bundles }`，回滚靠它 |
| `cordis.patch.yml.before` | 被追加/覆盖前的原文件（`--force-config` 或合并时不覆盖你条目，但会先留底） |
| `<其它文件>.before` | 被覆盖的其它配置文件原件 |
| `skills\<档位>\<技能名>\` | 被覆盖前的技能（`dsh` / `agents` 两档） |

### 手动还原（不跑 ROLLBACK 时）

1. 在 `<store>\backups` 里挑最新那个含 `deps-before.json` 的目录。
2. 把目录里的 `cordis.patch.yml`、`cordis.yml`、`pnpm-workspace.yaml`、`pnpm-lock.yaml` 复制回 `<profile>`。
3. `package.json` 用 `deps-before.json` 的 `dependencies` / `bundles` 手工对齐：删掉本包新增的包名，把 `dsh.profile.bundles` 改回快照列表。
4. 删掉多余链接：`Remove-Item "<profile>\node_modules\<包名>" -Recurse -Force`（只删本包带进来的）。
5. 技能还原：把 `skills\dsh\*` 与 `skills\agents\*` 复制回 `<home>\skills` 与 `%USERPROFILE%\.agents\skills`，然后重开 App（界面有残留面板就刷新一次页面）。

改完任何配置，最省事的自检顺序是：`VERIFY.cmd`（包没坏）→ `DOCTOR.cmd`（环境对）→ GUI 里发一句话（模型通）。
