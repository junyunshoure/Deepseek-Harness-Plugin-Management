# DeepSeek Harness 插件整合包 v2.1.0 —— 常见问题（Windows）

适用：DeepSeek Harness 桌面版 **0.2.x**（本包支持 `>=0.2.0 <0.4.0`，构建基准 `0.2.1-rc.2`）+ 插件整合包 **v2.1.0**。
本文件位置：解压目录下的 `docs\常见问题.md`。命令默认粘进 **PowerShell** 执行；`%LOCALAPPDATA%` = `C:\Users\<你>\AppData\Local`，`%USERPROFILE%` = `C:\Users\<你>`，`D:\DSHPack` 指你解压出来的 `DSH-Plugins-v2.1.0` 目录（按实际路径替换）。
每节都是「症状 → 原因 → 怎么办 → 还不行交给谁」，可单独看，不必按顺序读。

---

## 快速自查三步

| 步骤 | 双击 | 它做什么 | 看什么 |
| --- | --- | --- | --- |
| 1 | `VERIFY.cmd` | 逐文件比 SHA-256，**不改任何东西** | 末尾有 `✓ 只做校验，未改动任何文件。` |
| 2 | `DOCTOR.cmd` | 体检：安装目录、内核版本、profile、bundle、插件条目、端口、上次安装结果、备份数 | 行首 `✓ / ! / ✗`，最后一行「结论」 |
| 3 | 不双击 | 读结果文件 | `%LOCALAPPDATA%\DSHPluginsPack\last-result.json` 的 `ok` 与 `error` |

`VERIFY.cmd` 正常输出形如 `✓ SHA-256 完整性校验通过：N 个文件` / `✓ 目标内核版本：0.2.1-rc.2` / `✓ 本包版本：2.0.0，插件包数：32，技能：6`。有一段不像这样就跳到〈解压不完整 / 路径太长 / checksums 校验失败〉。

`DOCTOR.cmd` 会打印 Desktop 目录、内核版本、profile 路径、`已启用 bundle：N 个；依赖：M 个`、`本包插件已挂载：x/32`、`插件条目组合：256 个`、运行中的端口、四个记忆服务端口状态、上次安装结果、可回滚备份数。`✓` 正常／`!` 可以先放／`✗` 阻塞，先解决 `✗`。

| `last-result.json` 字段 | 含义 | 用法 |
| --- | --- | --- |
| `ok` | `true` 成功 / `false` 失败 | 第一步就看它 |
| `error` | 失败原因（安装器的中文原文） | `ok:false` 时的核心线索 |
| `mode` | `install` / `doctor` / `rollback` / `uninstall` | 这份结果是谁写的 |
| `installed` / `skipped` / `failed` | 已挂载 / 跳过 / 失败的包 | 应有 32 个挂载；`failed` 非空就要看日志原文 |
| `bad` / `warn` | 体检的阻塞项 / 提醒项 | 仅 `mode:doctor` |
| `store` / `backup` | 持久目录 `%LOCALAPPDATA%\DSHPluginsPack\v2.1.0-windows` / 本次安装前备份 | 回滚与数据都在这下面 |

## 安装类问题

### `INSTALL.cmd` 一闪而过，或者满屏中文乱码

**症状**：窗口闪一下就没；或中文显示成 `����`。
**原因**：闪退多半是解压不全、被杀软/SmartScreen 拦、或参数报错（`pause` 之前进程就退了）；乱码是控制台字体问题（脚本内部已执行 `chcp 65001`）。
**怎么办**：

1. 改用 PowerShell 跑安装器，报错会留在窗口里：
   `cd "D:\DSHPack"; powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Action install; "退出码=$LASTEXITCODE"`
2. 乱码：右键窗口标题栏 →「属性」→「字体」选 `Consolas` 或 `Lucida Console`，重开窗口。
3. 确认关键文件都在解压目录：
   `"D:\DSHPack\install.ps1","D:\DSHPack\install-helper.cjs","D:\DSHPack\payload\node_modules","D:\DSHPack\checksums.json" | ForEach-Object { "$_ = $(Test-Path $_)" }`

**还不行**：把 PowerShell 窗口的完整输出 + `last-result.json` 全文交给整合包维护者。

### 提示「没有自动找到 DeepSeek Harness 安装目录」

**症状**：报 `没有自动找到 DeepSeek Harness 安装目录`，或让你手填路径。
**原因**：安装器按这个顺序找四个位置：`%LOCALAPPDATA%\Programs\DeepSeek Harness`、`%LOCALAPPDATA%\DeepSeek Harness`、`%ProgramFiles%\DeepSeek Harness`、`%ProgramFiles(x86)%\DeepSeek Harness`。装到别处就没人命中，它会停下来问你要路径。
**怎么办**：

1. 要给的目录是**含 `DeepSeek Harness.exe` 的那个目录**，不是 `resources`、更不是 `resources\app.asar`：
   `Get-ChildItem "$env:LOCALAPPDATA\Programs\DeepSeek Harness" -Filter 'DeepSeek Harness.exe'`
2. 手动指定（任选一种）：
   `.\INSTALL.cmd -DesktopDir "D:\Apps\DeepSeek Harness"`
   `$env:DSH_DESKTOP_DIR="D:\Apps\DeepSeek Harness"; .\INSTALL.cmd`
   或 `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Action install -DesktopDir "D:\Apps\DeepSeek Harness"`
3. 目录里没有 exe 就不是安装目录，继续往上/下一层找，直到看见 exe。

**还不行**：把 `Get-ChildItem "你的目录" | Select-Object Name` 的输出交给维护者，判断你装的是哪种发行形态。

### 提示「没有找到 Desktop 的 profile」

**症状**：`没有找到 Desktop 的 profile（C:\Users\你\.dsh\profiles\desktop）`。
**原因**：`%USERPROFILE%\.dsh\profiles\desktop` 是 App **第一次启动时自己生成**的；空壳刚装好、一次没开过 App，目录就还不存在。
**怎么办**：

1. 打开一次 DeepSeek Harness，等主界面完全出来（首次启动建目录，慢正常）。
2. 从**系统托盘**右键图标选「退出」完全关掉（只点窗口 × 可能还有进程）。
3. 验证并确认没有残留进程：
   `Test-Path "$env:USERPROFILE\.dsh\profiles\desktop\package.json"`
   `Get-Process -Name 'DeepSeek Harness' -ErrorAction SilentlyContinue | Select-Object Id`
4. 再跑 `INSTALL.cmd`。若你改过 `DSH_HOME`，profile 会跟着挪，用 `"DSH_HOME=$env:DSH_HOME"` 看一眼真实位置。

**还不行**：把 `Get-ChildItem "$env:USERPROFILE\.dsh" | Select-Object Name` 与 `last-result.json` 交给维护者——数据目录可能被别的版本改过名。

### 提示「内核版本 … 不在本包支持范围」

**症状**：`内核版本 0.3.x 不在本包支持范围（>=0.2.0 <0.3.0）内`，或提示 profile 不是标准 Desktop profile（缺 `@deepseek-ai/dsh-base` / `dsh-web-app`）。
**原因**：本包只对 0.2.x 内核的插件接口验证过；0.3.x 起清单格式与 bundle 写法可能变化，硬装会得到「界面在、功能全废」。
**怎么办**：

1. 看真实版本：
   `(Get-Content -Raw "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh-app-boot\package.json" | ConvertFrom-Json).version`
2. 是 0.2.x 却报这条：机器上有两份 DeepSeek Harness，安装器认错了目录——用 `-DesktopDir` 指到正在用的那份，并看 `DOCTOR.cmd` 报的版本。
3. 是 0.3.x 或更新：把「整个整合包 + `docs\AI-agent-适配指南.md`」交给 DSH 里的 AI agent，按新内核清单格式重排 bundle 与插件条目（话术见最后一节）。
4. 真要硬装（例如 0.3.x 只是小改名）：`.\install.ps1 -ForceKernel`（等于给 helper 传 `--force-kernel`），装完立刻跑 `DOCTOR.cmd` 看哪些入口没挂上——能装上不等于能用，出问题还是第 3 步交给 AI agent。

**还不行**：把 `DOCTOR.cmd` 全文（含真实内核版本与 profile 路径）交给维护者，请他给对应内核的适配版。

### 选了 A 全新安装，却报「目标 profile 已有其他插件」

**症状**：`选的是"全新安装"，但目标 profile 已有其他插件（N 个依赖 / M 个 bundle）`。
**原因**：A 模式要求「空壳」——除内核自带 4 个 bundle 外不该有别的东西。你装过别的插件、旧版整合包或用市场装过东西，就不满足。
**怎么办**：

1. 重跑 `.\INSTALL.cmd`，在提示 `输入 A / B / C（直接回车 = B 智能合并）` 时直接回车（B 模式：同名插件跳过、不覆盖，最安全）。
2. 免交互一步到位：`powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Action install -Mode merge -Yes`
3. 就是要用本包版本覆盖旧版，用 C（覆盖前整份备份）：`... -Mode backup -Yes`
4. 想看清挡路的是谁：`$m = Get-Content -Raw "$env:USERPROFILE\.dsh\profiles\desktop\package.json" | ConvertFrom-Json; $m.dependencies.PSObject.Properties.Name`

**还不行**：把第 4 步输出 + 报错原文交给维护者，请他判断是否适合合并。

### 解压不完整 / 路径太长 / checksums 校验失败

**症状**：`缺少文件（包可能没有完整解压，或解压工具丢了长路径文件）：payload/...`、`文件内容与校验清单不符（下载或解压损坏）`、`解压不完整：没有 payload\node_modules`。
**原因**：`payload\node_modules` 有 2 万多个文件、最深路径超出 Windows 自带解压的舒适区，用资源管理器双击解压常静默丢文件；下载中断会让 SHA-256 对不上。
**怎么办**：

1. 用 **7-Zip**（右键 →「7-Zip」→「提取到…」）解到短路径如 `D:\DSHPack`；别解到桌面深层目录或 OneDrive 同步目录。
2. 解压后先跑 `.\VERIFY.cmd`，它会把第一个出问题的文件路径打出来。
3. 校验下载件本身：`Get-FileHash "D:\下载\DSH-Plugins-v2.1.0-Windows-x64.zip" -Algorithm SHA256` 与同名 `.sha256` 文件里的值比对；不一致就重新下载（别用断点续传拼出来的文件）。
4. 急着先装、跳过校验（不推荐，出问题时没有判据）：`install.ps1` 没暴露 `--skip-verify`，直接调 helper：
   `$env:ELECTRON_RUN_AS_NODE="1"; cd "D:\DSHPack"; & "$env:LOCALAPPDATA\Programs\DeepSeek Harness\DeepSeek Harness.exe" --expose-internals ".\install-helper.cjs" --desktop-dir "$env:LOCALAPPDATA\Programs\DeepSeek Harness" --mode merge --skip-verify`

**还不行**：把 `VERIFY.cmd` 完整输出 + `.zip` 的 SHA-256 + 你的解压路径交给维护者。

### 某个插件「挂载失败」

**症状**：`有 N 个插件挂载失败：xxx`；或出现 `离线挂载失败，改用普通模式重试（需要能访问 npm 源）…` 后仍失败。
**原因**：默认走 `plugin add --offline` 从 `payload` 就地链接；这条路走不通会退回普通模式，那一步要联网拉元数据，被 npm 源、代理、公司网络挡住就失败。
**怎么办**：

1. 看 `last-result.json` 的 `failed` 字段：全部失败通常是网络/目录问题，不是包的问题。
2. 查源与代理（不用装 Node，直接看文件）：
   `Get-Content "$env:USERPROFILE\.npmrc" -ErrorAction SilentlyContinue; Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\.npmrc" -ErrorAction SilentlyContinue; "HTTP_PROXY=$env:HTTP_PROXY"; "HTTPS_PROXY=$env:HTTPS_PROXY"`
   有 Node 时 `npm config get registry`；内网源换成公共源再试：`npm config set registry https://registry.npmmirror.com`
3. 往上翻安装日志找 npm 原文：`ERR_PNPM_*` / `ETIMEDOUT` / `EACCES` / `ENOTFOUND` 分别对应源不可达 / 超时 / 权限 / DNS。
4. 单独重挂一个（只改 `NAME`）：
   `$env:ELECTRON_RUN_AS_NODE="1"; & "$env:LOCALAPPDATA\Programs\DeepSeek Harness\DeepSeek Harness.exe" --expose-internals "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh-desktop-host\lib\cli.js" plugin --profile desktop add --offline --ignore-scripts --save-exact "link:D:/DSHPack/payload/node_modules/NAME"`
5. 报 `没生成链接` / `bundle 未启用`：多为符号链接被拦（杀软、`node_modules` 被占用）。完全退出 App、临时关实时防护后重跑一次。

**还不行**：把「失败那行往前 50 行」的完整输出 + `failed` 字段交给维护者。

### 装完了，但界面一点变化都没有

**症状**：窗口显示 `安装完成`，侧边栏还是老样子。
**原因**：插件在 App 启动时一次性挂载；安装期间 App 没完全退出、或页面还开着旧前端资源，就看不到新入口。
**怎么办**：

1. 托盘右键 →「退出」，确认进程没了再打开：`Get-Process -Name 'DeepSeek Harness' -ErrorAction SilentlyContinue | Select-Object Id`
2. 已打开的先按 `Ctrl + R` 刷新一次页面（很多「装了没反应」刷新就好）。
3. 「设置 → 插件」里看对应条目是否 **active**，被停用的手动打开。
4. 用 `DOCTOR.cmd` 交叉验证：`本包插件已挂载：32/32`、`插件条目组合：256 个`、`已启用 bundle：36 个`。对得上就是显示问题；对不上回〈某个插件挂载失败〉。
5. 首次加载 32 个插件要 20–60 秒，白屏等待属正常，别中途强杀。

**还不行**：把 `DOCTOR.cmd` 输出 + `%APPDATA%\@deepseek-ai\dsh-desktop\logs` 里最新的 `crash-*-web-boot.log` 交给维护者。

## 使用类问题

### 侧边栏没有「技能 / 记忆融合 / 功能说明 / Ollama / 清理 / 工作台」入口

| 入口 | 来自 bundle |
| --- | --- |
| 技能融合中心 | `dsh-skill-fusion` |
| 记忆融合 | `dsh-memory-fusion` |
| 功能说明 | `dsh-feature-profiles` |
| Ollama | `dsh-ollama` |
| 清理 | `dsh-purge` |
| 工作台 | `@local/dsh-client-ui-workbench` |

**原因**：入口由 bundle 里的条目渲染。三种可能：bundle 没写进 `dsh.profile.bundles`、条目被停用、页面没刷新。
**怎么办**：

1. 查 bundle 是否在（期望 6 行）：
   `$m = Get-Content -Raw "$env:USERPROFILE\.dsh\profiles\desktop\package.json" | ConvertFrom-Json; $m.dsh.profile.bundles | Where-Object { $_ -match 'skill-fusion|memory-fusion|feature-profiles|ollama|purge|workbench' }`
2. 少了就重跑 B 模式补齐，别手写 `package.json`（错一个逗号 App 起不来）。
3. 都在就去「设置 → 插件」搜 `skill-fusion` / `purge` / `ollama`，把条目开关打开，再 `Ctrl + R`。
4. `DOCTOR.cmd` 里 `插件条目组合：256 个` 是基准值，差得多说明有 bundle 加载时被跳过，输出里会有 `加载时被跳过的 bundle：...`。

**还不行**：把第 1 步输出 + `DOCTOR.cmd` 全文交给维护者。

### 设置里模型列表是空的，或者调不通

**症状**：设置 → 模型里没有模型，或有列表但一发消息就报连接失败 / 401。
**原因**：整合包不带你的账号和密钥。模型地址在 profile 的 `cordis.patch.yml`，打包时留的是占位符 `https://YOUR-ENDPOINT.example.com`；密钥要写在 `%USERPROFILE%\.dsh\.credentials.yaml`（或被 `apiKeyEnv` 指向的环境变量）。
**怎么办**：

1. 找出所有要改的字段：
   `Select-String -Path "$env:USERPROFILE\.dsh\profiles\desktop\cordis.patch.yml" -Pattern 'baseURL|YOUR-ENDPOINT|apiKeyEnv'`
2. 先备份再改：`Copy-Item "$env:USERPROFILE\.dsh\profiles\desktop\cordis.patch.yml" "$env:USERPROFILE\.dsh\profiles\desktop\cordis.patch.yml.bak-$(Get-Date -Format yyyyMMdd-HHmmss)"`，然后把 `YOUR-ENDPOINT.example.com` 换成你的中转站或官方地址。
3. 密钥写进 `%USERPROFILE%\.dsh\.credentials.yaml`，**键名与 `apiKeyEnv` 的值完全一致**（配置写 `apiKeyEnv: OPENAI_API_KEY`，这里就写 `OPENAI_API_KEY: sk-...`）。也可以走「设置 → 模型」填地址与密钥。
4. 托盘退出再重开 App（配置在启动时读）。
5. 自查：`Test-NetConnection 127.0.0.1 -Port 61787 -InformationLevel Quiet`（App 端口，应 True）；`(Invoke-WebRequest "https://你的中转站/v1/models" -Headers @{Authorization="Bearer 你的密钥"} -TimeoutSec 10).StatusCode`

**还不行**：把 `cordis.patch.yml` 里 `baseURL` 那几行（**密钥打码**）+ 报错原文交给维护者；密钥本身不要外传。

### 记忆融合 / 记忆检索报错

**症状**：记忆面板转圈或报错；检索报连接失败。
**原因**：记忆功能是「前端插件 + 本地服务」两半。插件在整合包里，服务本体（ReMe / OpenViking / Hindsight / WeKnora）**不在**本包，要单独跑 `SETUP-SERVICES.cmd`，且它只从 `payload\services` 安装。
**怎么办**：

1. 探端口（ReMe 2333、OpenViking 1933、Hindsight 8888、WeKnora 8080）：
   `foreach ($p in 2333,1933,8888,8080) { "$p = " + (Test-NetConnection 127.0.0.1 -Port $p -InformationLevel Quiet -WarningAction SilentlyContinue) }`
2. 全是 `False` → 跑 `.\SETUP-SERVICES.cmd`（会建独立 Python 环境，2–5 分钟）。
3. 若它打印「这个包里没有服务本体（payload/services 不存在），这是正常的」，说明你下的是插件包：把 Services 包的 `payload\services` 整个复制到 `%LOCALAPPDATA%\DSHPluginsPack\v2.1.0-windows\payload\services` 再跑一次。
4. 装完重开 App，`DOCTOR.cmd` 的 `本地记忆服务：...=在线` 应变在线。只有部分在线是正常的——用到哪个装哪个，没装的面板空着不代表坏了。

**还不行**：把 `SETUP-SERVICES.cmd` 完整输出 + 哪几个端口在线交给维护者。

### 技能列表是空的

**症状**：技能面板 / 技能融合中心一个技能都没有。
**原因**：技能是纯文件，装在两个位置，App 启动时扫一次；装完不刷新页面看不到；整组被关掉也会显示为空。
**怎么办**：

1. 确认文件在（本包 6 个：`dsh` 档 4 个、`agents` 档 2 个）：
   `Get-ChildItem "$env:USERPROFILE\.dsh\skills","$env:USERPROFILE\.agents\skills" -Directory -ErrorAction SilentlyContinue | Select-Object FullName`
2. 目录空 → 重跑 `INSTALL.cmd`（B 模式）。已存在的技能会先备份到 `backups\<时间戳>\skills\...` 再覆盖，不会闷掉你的版本。
3. 有目录但界面空 → `Ctrl + R` 刷新，或托盘退出重开；技能融合中心按来源分组，组头部的整组开关打开试试。
4. 手动放进目录的技能，重开一次 App 或点面板刷新。

**还不行**：把两个目录的 `Get-ChildItem` 输出 + 技能面板截图交给维护者。

### 上下文 / 缓存、Ollama 面板、清理面板各自的坑

**上下文 / 缓存（billion-context）**：面板里的 token 是**压缩后**的，比原文小属正常；被压缩掉的内容得让 AI 去解压，面板里点不开原文；上下文吃紧时先压缩再继续，硬塞的报错很难懂。
**Ollama 面板**：没装 Ollama 就没有本地模型，面板空着、按钮点不动都正常，不是装坏了。装了要确认服务在跑且模型在本地：`Test-NetConnection 127.0.0.1 -Port 11434 -InformationLevel Quiet`、`ollama list`；面板选不到模型 = `ollama list` 里也没有，先 `ollama pull qwen2.5:7b` 再回来刷新。
**清理面板（dsh-purge）**：删东西前会备份，备份在 `%USERPROFILE%\.dsh\dsh-purge`（以及 `%USERPROFILE%\.dsh\undo-snapshots` 等快照目录），删错先去那里找；会话历史、附件、缓存是三类不同的东西——删缓存不影响会话，删会话就是真删；清理只对本机磁盘有效，别指望清服务端或网盘。
**还不行**：说明哪个面板的哪个按钮 + 报错原文，交给维护者。

## v2.1.0 新增问题

### 升级后插件"消失"了，但 DSH 照常启动

这是 v2.1.0 最常见的一个坑，**而且它不报错**。

- 原理：profile 的 `package.json` 里每个插件是一条 `link:<绝对路径>`。载荷目录被删/盘符变了以后，这个链接就断了；DSH 加载时会**静默跳过**这一个 bundle（只往日志里写一行 `dsh: skipping profile bundle "..."`），界面照常打开。
- 判断：跑 `DOCTOR.cmd`，看"link: 目标全部存在"这行；不通过它会列出断链的包名与目标路径。
- 修复：`install.ps1 -Action repair`（或 `install.ps1 -Action install` 选 E）。它只重挂本包声明的插件，不新增别的。
- 自查命令（想看原始证据）：
  ```powershell
  $p = "$env:USERPROFILE\.dsh\profiles\desktop"
  (Get-Content "$p\package.json" -Raw | ConvertFrom-Json).dependencies.PSObject.Properties |
    Where-Object { $_.Value -like 'link:*' } |
    ForEach-Object { [pscustomobject]@{ 包 = $_.Name; 存在 = Test-Path $_.Value.Substring(5) } } |
    Format-Table -AutoSize
  ```

### `PRUNE.cmd` 跑了却什么都没删

三种正常情况，都不是故障：

1. **载荷还没满 7 天**（默认 `-KeepDays 7`）。急着腾空间：`install-helper.cjs --prune-old --keep-days 0 --yes`。
2. **那个载荷仍被某个 profile 的 `link:` 引用**。规则是"仍被引用的永不删"——删了插件就断链（见上一条）。先升级到新载荷（D 模式），旧载荷才会被释放。
3. **只跑了预演**。不带 `--yes`（或 `PRUNE.cmd` 里不确认）时它只打印计划，不动文件。

自查：`PRUNE.cmd` 会把"保留 <路径>（原因）"逐条打出来。

### `MAINTAIN.cmd` 报"检测到多个附录块，已跳过"

`~/.dsh/AGENTS.md` 里有 2 个以上 `ALIGNMENT_PROTOCOL v1.0` 标记块（通常是手工复制粘贴叠加造成的）。它**故意不自动清**——删错段落会丢你自己的规则。

做法：手工把多余的块删到只剩一对（`<!-- ALIGNMENT_PROTOCOL v1.0 START ... -->` 到 `<!-- ALIGNMENT_PROTOCOL v1.0 END -->`），再跑一次 `MAINTAIN.cmd`。它会做**替换**而不是追加，写完自己断言"START 1 个 / END 1 个"。

### 升级时某个包报"离线 store 里没有这个 tarball"

例如 `[ERR_PNPM_NO_OFFLINE_TARBALL]`，通常还带一个 `codeload.github.com/...` 的地址。

- 根因：你的 profile 里有一条 **git 依赖**（常见是 `treg-dsh` 这类 GitHub tarball 依赖），而整合包只带 npm 包的离线 store。
- v2.1.0 的处理：先 `--offline`，再 `--offline --config.lockfile=false`；仍失败就**默认不联网**、记录成"告警"继续装完，最后打印三条补挂办法（含显式 `-Action upgrade -AllowNetwork`）。
- 为什么不自动联网：联网会把 200+ 个实体包装进 profile，破坏"全部插件 `link:` 到载荷"的离线语义，升级就不再可回滚了。
- 你也可以就让它告警：装完 `DOCTOR.cmd` 确认其余插件 32/32 挂上即可；那个 git 依赖的包单独 `dsh plugin --profile desktop add <包名>` 补。

### 装完了，`~/.dsh/AGENTS.md` 里没看到对齐协议

v2.1.0 起安装结束后会自动写一次，正常情况下你什么都不用做。没写上有三种原因：

1. **你选了 `-SkipAppendix`**：那就确实不写。重跑 `install.ps1 -Action appendix` 即可（这条只写 AGENTS.md，别的都不碰）。
2. **写失败但不影响安装**：安装结果里有 `appendix` 字段，`ok: false` 时看 `hint`。最常见是 `~/.dsh/AGENTS.md` 里有**两个以上**标记块（历史上手工追加过），它会拒绝自动处理——手工删到只剩一对 `<!-- ALIGNMENT_PROTOCOL v1.0 START ... -->` / `<!-- ... END -->` 再重跑。
3. **看了老会话**：`AGENTS.md` 是会话启动时读的，**已经开着的会话不会重新加载**。新开一个会话再看。

> 想确认到底写进去没有：`Select-String -Path "$env:USERPROFILE\.dsh\AGENTS.md" -Pattern 'DEPTH_MODE|ALIGNMENT_PROTOCOL'`，正常应看到 `## DEPTH_MODE: ask` 以及 START / END 各一行。

## 回滚与卸载

### `ROLLBACK.cmd` 怎么用

**症状**：装完想撤回（界面变样、插件冲突、想重选安装模式）。
**原因**：每次安装都会在持久目录留一份「安装前快照」，回滚就是按快照还原依赖与 bundle 名单。
**怎么办**：

1. 托盘完全退出 DeepSeek Harness。
2. 双击 `ROLLBACK.cmd`，或 `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Action rollback`
3. 它默认取**最新一份备份**（`store\backups` 下按时间戳排序取最大），打印 `使用备份`、`回滚到`、`已还原配置`、`已移除本包依赖`、`bundle 列表已回到 N 个`。
4. 重开 App 生效；还有残留面板就 `Ctrl + R`。
5. 直接看备份内容核对：`Get-ChildItem "$env:LOCALAPPDATA\DSHPluginsPack\v2.1.0-windows\backups" | Sort-Object Name | Select-Object Name`；`Get-Content "$env:LOCALAPPDATA%\DSHPluginsPack\v2.1.0-windows\backups\<时间戳>\deps-before.json"`

| 备份目录 `%LOCALAPPDATA%\DSHPluginsPack\v2.1.0-windows\backups\<时间戳>` 里的东西 | 是什么 |
| --- | --- |
| `deps-before.json` | 安装前的依赖与 bundle 名单（含 `at`、`mode`），回滚就靠它 |
| `package.json` / `pnpm-lock.yaml` / `pnpm-workspace.yaml` / `cordis.yml` / `cordis.patch.yml` | 安装前的配置原件（存在才备份） |
| `skills\<档位>\<技能名>` | 被覆盖前的旧版技能 |
| `*.before` | `--force-config` 覆盖单文件前的备份 |
| `uninstall-<时间戳>` | `UNINSTALL.cmd` 自己留的配置备份 |

**还不行**：`ROLLBACK.cmd` 只回滚最新一份；要指定更早的，把上表文件手工拷回 `%USERPROFILE%\.dsh\profiles\desktop\`，再按下一节改 `package.json`。

### 备份目录被删了怎么办

**症状**：`没有找到任何备份`，或 `备份里缺少 deps-before.json`。
**原因**：`%LOCALAPPDATA%\DSHPluginsPack` 被清理软件或手动删过；或这次安装没走到备份那一步（v1 旧流程）。
**怎么办**：

1. 看还有没有残留：`Get-ChildItem "$env:LOCALAPPDATA\DSHPluginsPack\v2.1.0-windows\backups" -ErrorAction SilentlyContinue | Select-Object Name`
2. 有 C 模式（备份后覆盖）留下的备份就能用：整份拷成一个新的时间戳目录，再跑 `ROLLBACK.cmd`。
3. 一份都没有 → 手改 `package.json`（先备份，按名单删依赖与 bundle）：
   `$mf="$env:USERPROFILE\.dsh\profiles\desktop\package.json"; Copy-Item $mf "$mf.bak-$(Get-Date -Format yyyyMMdd-HHmmss)"; $names=@((Get-Content -Raw "D:\DSHPack\migration.json"|ConvertFrom-Json).packages.name)+"dsh-migration-plugin-state"; $m=Get-Content -Raw $mf|ConvertFrom-Json; foreach($n in $names){$m.dependencies.PSObject.Properties.Remove($n)}; $m.dsh.profile.bundles=@($m.dsh.profile.bundles|Where-Object{$names -notcontains $_}); $m|ConvertTo-Json -Depth 20|Set-Content -Encoding utf8 $mf`
4. 删掉名单里那些包在 profile 里的链接（不动别人的）：`foreach($n in $names){$t=Join-Path "$env:USERPROFILE\.dsh\profiles\desktop\node_modules" ($n -replace '/','\'); if(Test-Path $t){Remove-Item $t -Recurse -Force}}`
5. 改完重开 App。真弄坏了还有 `UNINSTALL.cmd` 兜底；把 profile 目录改名让 App 重新生成是最后的办法（会丢你自己的插件配置）。

**还不行**：把 `package.json` 全文交给维护者，请他给一份改好的版本。

### `UNINSTALL.cmd` 卸载后还有残留

**症状**：App 里干净了，磁盘上还留着一堆东西。
**原因**：卸载只动「配置里的依赖与 bundle」，刻意不动技能文件、备份、持久目录——这些是数据，删了找不回来。
**怎么办**：

1. 卸载：`powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Action uninstall`
2. 按需手工清（每条都先确认路径再删）：
   `Get-ChildItem "$env:USERPROFILE\.dsh\skills","$env:USERPROFILE\.agents\skills" -Directory | Select-Object FullName`
   `Remove-Item "$env:LOCALAPPDATA\DSHPluginsPack\v2.1.0-windows" -Recurse -Force`（payload 有 500MB 上下）
   `Get-ChildItem "$env:USERPROFILE\.dsh\profiles\desktop" -Filter '*.pack-sample'`
3. 卸载不删的还有：`backups\uninstall-<时间戳>`、`feature-profiles` 文档目录、`cordis.patch.yml`（你改过的模型地址，别乱删）。
4. 彻底回空壳：卸载 → 删持久目录 → 删本包带的几个技能目录 → 重开 App 按提示重新初始化。

**还不行**：把 `last-result.json`（`mode:uninstall` 那份）和你想删的目录清单交给维护者确认。

## 安全与隐私

| 包里不带的东西 | 说明 |
| --- | --- |
| 账号 / 登录态 | 没有 cookie、token、会话文件 |
| API 密钥 | 模型地址与密钥字段都是占位符，例如 `https://YOUR-ENDPOINT.example.com` |
| `.credentials.yaml` | 密钥只在 `%USERPROFILE%\.dsh\.credentials.yaml`，永远不随包分发 |
| 记忆数据 / 聊天记录 | 包内状态 bundle `dsh-migration-plugin-state` 只存「插件启停状态」，不含会话与记忆正文 |

想确认包里到底有什么：

```powershell
$b = "D:\DSHPack"
(Get-Content -Raw "$b\inventory.json" | ConvertFrom-Json).counts
(Import-Csv "$b\plugins.csv").Count          # 应为 256
Get-Content "$b\插件完整清单.txt" -TotalCount 6
(Get-Content -Raw "$b\checksums.json" | ConvertFrom-Json).files.Count
```

| 文件 | 内容 |
| --- | --- |
| `inventory.json` | `counts`（32 个依赖包、6 个技能、47 篇功能说明 + always.json、36 个 bundle、256 个插件条目）+ 每个条目的启停状态 |
| `plugins.csv` | 256 行条目表：条目 ID、包名、所属 bundle、启停状态 |
| `插件完整清单.txt` | 给人看的清单：bundle 分组 + 条目树 |
| `bundles.csv` | 36 个 bundle 及条目数、停用条目数 |
| `checksums.json` | 逐文件 SHA-256，`VERIFY.cmd` 比对的就是它 |

顺手确认没有密钥混进去（下面两条**都应该没有输出**）：
`Select-String -Path "D:\DSHPack\config\*","D:\DSHPack\migration.json" -Pattern 'sk-[A-Za-z0-9]{10,}' -ErrorAction SilentlyContinue`；`Get-ChildItem "D:\DSHPack" -Recurse -Filter '.credentials.yaml' -ErrorAction SilentlyContinue`
