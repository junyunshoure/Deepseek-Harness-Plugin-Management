# DSH 插件整合包 v2.0.0 · 使用说明书

> 适用：Windows 10/11 x64，DeepSeek Harness `0.2.x`；macOS 见 [`../macos/INSTALL-MAC.md`](../macos/INSTALL-MAC.md)
> 读者：只装了一个 DSH 空壳、没有配置、没有其它插件的人。按顺序读，每节都能单独用。

---

## 1. 这份说明书怎么用

| 你的情况 | 直接跳到 |
|---|---|
| 刚下载，什么都还没做 | 第 2 节 → 第 3 节 → 第 4 节（必读三节） |
| 装完了，但模型调不通 | 第 4 节 |
| 装完了，不知道多出来的侧边栏入口是干什么的 | 第 5、6 节 |
| 想要跨会话记忆 / 本地知识库 | 第 8 节 |
| 想换自己的模型、改配置 | [`配置参考.md`](配置参考.md) |
| 报错了 | 第 11 节 → [`常见问题.md`](常见问题.md) |
| 想升级、回滚、卸载、换机器 | 第 10 节 |
| 想加包里没有的插件 | [`AI-agent-适配指南.md`](AI-agent-适配指南.md) |

术语先对齐：

- **内核**：DeepSeek Harness 本体（`DeepSeek Harness.exe` + `resources\app.asar`）。本包按 `0.2.1-rc.2` 构建。
- **profile**：一套「用哪些插件、怎么配」的档案。本包只动 `desktop` 这一个，路径 `%USERPROFILE%\.dsh\profiles\desktop`。
- **bundle**：一个可启停的插件集合。包里有 36 个。
- **条目（entry）**：bundle 里真正跑起来的一行插件实例，有 `id`。包里有 256 个。
- **持久目录**：安装时载荷被复制到 `%LOCALAPPDATA%\DSHPluginsPack\v2.0.0-windows`，插件链接指向这里。**这个目录不能删**。

## 2. 装机前你需要知道的三件事

### 2.1 确认内核版本

```powershell
(Get-Content -Raw "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh-app-boot\package.json" | ConvertFrom-Json).version
```

- 输出 `0.2.x` → 直接装。
- 输出别的版本 → 仍可装（会提示内核与基准不同），装完先跑 `DOCTOR.cmd`；不放心就看 [`AI-agent-适配指南.md`](AI-agent-适配指南.md)。
- 报「找不到路径」→ 内核装在别处。右击 DSH 桌面快捷方式 → 属性 → 看「目标」里的目录，安装时用 `-DesktopDir "那个目录"`。

### 2.2 找一个短路径解压

- 推荐 `D:\DSH-Plugins-v2.0.0`、`C:\DSH-Pack`。
- 不要：桌面、`下载` 文件夹、`C:\Program Files`、带中文和空格的长路径、直接在压缩包预览窗口里双击。
- 原因：包里有 23,249 个文件、含超长路径，Windows 解压工具和 UAC 都会在这类位置出问题。

### 2.3 磁盘与时间预算

| 项 | 占用 |
|---|---|
| 压缩包 | 约 300 MB（插件包）+ 约 1.1 GB（服务包） |
| 解压后（插件包） | 约 520 MB |
| 持久目录副本 | 约 520 MB |
| 服务包解压 | 约 2.2 GB；装完四服务合计约 4.3 GB |
| 安装耗时 | 插件包 3–8 分钟（主要是逐文件校验）；服务包 5–20 分钟 |

不需要装 Node.js / Python / pnpm —— 安装器借 DSH 自带的 Electron 跑 Node 脚本。

## 3. 安装：逐步

### 3.1 双击 `INSTALL.cmd`

会出现一个黑窗口，标题类似：

```
====================================================================
  DeepSeek Harness 插件整合包 v2.0.0 —— 动作：install
====================================================================
```

它先找内核目录，再问你模式：

```
请选择安装模式：
  A 全新安装（目标 profile 必须干净）
  B 智能合并（只补缺，已有的一律不动）  ← 推荐
  C 备份覆盖（先备份再覆盖）
输入 A / B / C（直接回车 = B 智能合并）：
```

不知道怎么选就**直接回车**（B）。

### 3.2 三种模式的行为差异

| | A 全新安装 | B 智能合并 | C 备份覆盖 |
|---|---|---|---|
| 目标 profile 里没有第三方插件 | ✅ 正常装 | ✅ 正常装 | ✅ 正常装 |
| 目标 profile 里已有其它插件 | ❌ 中止（保护你） | ✅ 只补缺的，已有的跳过 | ✅ 覆盖，但先备份 |
| 已有同名但版本不同的包 | — | 保留你的（不降级也不升级） | 换成包内版本 |
| `cordis.patch.yml` 你已有 | — | 按条目补缺，你的条目一字不动 | 整份备份后覆盖 |
| 适合谁 | 新机器第一次装 | 装过别的东西、想叠加 | 想统一到本包版本 / 修坏掉的装法 |

### 3.3 正常输出长什么样

```
内核版本：0.2.1-rc.2（本包构建基准 0.2.1-rc.2）
复制到持久目录：C:\Users\你\AppData\Local\DSHPluginsPack\v2.0.0-windows
✓ 复制完成并通过校验
✓ 安装前备份：...\v2.0.0-windows\backups\2026-10-28T12-30-00
✓ 启用内核自带 bundle：@deepseek-ai/dsh-base, ...
[1/33] 挂载 billion-context@...
...
✓ 插件组合校验通过：256 个条目，36 个 bundle
✓ 合并配置：cordis.patch.yml 追加 17 条：ui-settings-account, ...
✓ 安装 47 篇功能 profile 说明到 profile/feature-profiles
✓ 安装技能：hindsight-coding-agent, ...
· 检测到服务本体（ReMe / OpenViking / Hindsight / WeKnora），本次未安装。需要时运行 SETUP-SERVICES.cmd。
```

看到 `安装完成` 与自动弹出的 DSH 窗口就成功了。结果同时写进两处：

- `<解压目录>\installation-result.json` 或持久目录里的同名文件
- `%LOCALAPPDATA%\DSHPluginsPack\last-result.json`（跨次记录）

### 3.4 安装器做了什么（想理解原理再看）

1. 校验 23,249 个文件的 SHA-256（`checksums.json`），防止解压残缺。
2. 把载荷复制到持久目录 —— 之后解压目录可以删，插件不受影响。
3. 备份目标 profile 的 `package.json`、`cordis.yml`、`cordis.patch.yml`、`pnpm-*.yaml`。
4. 用 DSH 自带插件 CLI 把 32 个包逐个 `plugin add link:<持久目录>\payload\node_modules\<包名>`。
5. 用内核的 `loadProfileDirectory` + `composeEntries` 把实际组合结果与 `inventory.json` 的 256 条对账。
6. 合并 `cordis.patch.yml`：只追加你没有的条目，末尾带一段「由 v2.0.0 追加」的注释方便你整段删掉。
7. 复制 47 篇能力手册、6 个技能（技能若已存在，旧版先备份到 `backups\skills\`）。
8. 写结果 JSON，然后启动 DSH。

## 4. 第一次打开：模型接入

装完能开界面，但**除了 DSH 账号自带的那档，其它模型都连不上**——因为配置里的地址是占位符 `https://YOUR-ENDPOINT.example.com`。

### 4.1 三条路，挑一条

**路线 A：只用 DSH 账号自带的模型（最省事）**

不填任何东西，直接用。默认模型在 `cordis.patch.yml` 的 `agent-default-model` 里：`provider: deepseek-account` / `model: deepseek-flash`。

**路线 B：用自己的中转站（大多数人选这个）**

1. 打开 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml`。
2. 全局替换：把 `https://YOUR-ENDPOINT.example.com` 换成你的中转站地址（例如 `https://xxx.example.com/v1`——是否带 `/v1` 看你的中转站说明）。
3. 密钥别写在这个文件里。去 **设置 → 模型** 里给每个 provider 填 Key；或者写进 `%USERPROFILE%\.dsh\.credentials.yaml`，键名要和 `apiKeyEnv` 一致（`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GROK_API_KEY`、`DEEPSEEKZHONGZHUAN_API_KEY` …）。
4. 完全退出 DSH 再打开（不是最小化）。

**路线 C：只用官方接口**

把 `llm-pi-ai` 那一段整段删掉（它列的是中转站上的模型清单），只留 `llm-deepseek`（本包已把它的 `baseURL` 设成 `https://api.deepseek.com`），在设置里填 DeepSeek 的 Key。

### 4.2 改完怎么验证

- 设置 → 模型：能列出模型、点「测试」不报 `401/404/ENOTFOUND`。
- 新开一个会话，问一句「你现在用的是哪个模型」，能正常回话即可。
- 还连不上：`DOCTOR.cmd` 看配置条目是否命中，再看 [`常见问题.md`](常见问题.md) 的「模型列表空/调不通」一节。

### 4.3 必填清单（不想逐个读文档就照这个做）

| 项 | 在哪 | 必填？ |
|---|---|---|
| 中转站地址 | `cordis.patch.yml` 里 9 处占位符 | 路线 B 必填 |
| 各 provider 的 Key | 设置 → 模型，或 `.credentials.yaml` | 用哪个填哪个 |
| 默认模型 | `cordis.patch.yml` → `agent-default-model` | 有默认值，可不动 |
| 服务地址 | 不需要手填，本地服务都是 `127.0.0.1` | — |
| workbench 根目录 | `payload\node_modules\@local\dsh-client-ui-workbench\cordis.patch.yml` 的 `root` | 留空 = `%USERPROFILE%\.dsh`，可不动 |

## 6. 六个本地插件怎么用

> 共同前提：改插件源码后要**完全重启 DSH**；源码在持久目录 `payload\node_modules\<包名>`。

### 6.1 功能档位 `dsh-feature-profiles`

- **它解决什么**：插件一多，工具手册全塞进上下文会撑爆。它让 agent 先看目录（`_index.md`），需要哪份才读哪份，读完才挂载那套工具。
- **怎么用**：正常提问即可。说「用 drawio 画个流程」→ agent 读 `drawai` 手册 → 工具出现。你不必点名。
- **看有哪些**：`%USERPROFILE%\.dsh\profiles\desktop\feature-profiles\` 下 47 个 md + `always.json`，`_index.md` 是目录。
- **加自己的**：丢一个带 frontmatter（`id`/`title`/`description`/`when`）的 md 进去，重启生效。
- **边界**：只负责「发手册」，不负责装插件。手册写了但插件没装，工具照样没有。

### 6.2 记忆融合 `dsh-memory-fusion`

- **它解决什么**：ReMe（个人记忆）和 OpenViking（资料/共享技能）原本两套入口，现在一个 `memory_search` 同时查，结果带来源、可对比。
- **怎么用**：「上次那个方案我们怎么定的」「我以前说过偏好吗」——agent 自动调；也可直接让它「用 memory_search 查 X」。
- **状态**：`memory_status` 看队列、捕获数、错误。
- **边界**：两端都离线时返回 `partial` 并说明原因；矛盾内容并列保留，不替你合并；不转换数据库格式。

### 6.3 技能融合中心 `dsh-skill-fusion`

- **入口**：侧边栏「技能」。
- **能做**：浏览全部技能（项目/自定义/用户/内置）、按来源分组、整组开关、市场导入、检查上游更新、逐文件差异预览后手动应用（应用前自动备份）、调用次数统计、诊断、回收站、新建技能向导。
- **策略**：选一个工作区 → 「全局默认」或「本项目覆盖」；有效状态 = `本项目覆盖 ?? 全局默认 ?? 启用`。
- **边界**：技能正文只读（避免丢字段）；项目按完整工作目录匹配，子目录不继承；只有用户级目录可写。

### 6.4 Ollama 面板 `dsh-ollama`

- **入口**：侧边栏「Ollama」。
- **能做**：发现本机 Ollama 的模型（名称/参数量/量化/大小/是否驻留）、逐个启用、加载/卸载、设默认、拉取/删除、面板内单次推理并显示实际选中的模型与速率。
- **边界**：不启动 Ollama、不接管全局模型配置、不自动回退云端。Ollama 没开时面板显示离线原因。
- **要先用本地模型聊天**：装 Ollama → `ollama pull qwen3:8b` → 打开面板确认在线 → 在面板里试一句。

### 6.5 逆向指挥体系 `dsh-purge`

- **它解决什么**：把「逆向一个 App」拆成五角色五阶段并留证据链，避免东一榔头西一棒槌。
- **怎么用**：说清目标（iOS/Android/Windows 哪个、拿到什么、要证明什么），让它按阶段推进。
- **边界**：只做分析与取证编排；产物是否合规由你判断。

### 6.6 多场景工作台 `@local/dsh-client-ui-workbench`

- **入口**：侧边栏「工作台」。
- **读什么**：`<root>\workbench\` 下的场景配置、`§〇` 交接、待办板、派单台账、体检结果，聚合成可点的一面墙，15 秒自动刷新。
- **root 在哪**：默认 `%USERPROFILE%\.dsh`（即读 `%USERPROFILE%\.dsh\workbench`）；想指向自己的工作区，改 `payload\node_modules\@local\dsh-client-ui-workbench\cordis.patch.yml` 的 `root` 后重启。
- **边界**：只读，不写文件、不碰会话。目录为空时页面是空的。

## 7. 技能与能力手册

### 7.1 技能装到哪了

| 层 | 路径 | 包内提供的 |
|---|---|---|
| DSH 用户技能 | `%USERPROFILE%\.dsh\skills\` | 6 个全在这 |
| Agent 通用技能 | `%USERPROFILE%\.agents\skills\` | 装了同名的会同步一份 |

装的时候如果同名技能已存在，旧版会先备份到 `backups\skills\<层>\<名字>` 再覆盖。

### 7.2 怎么用

- 侧边栏「技能」里能看到全部，点开看正文。
- 会话里说「用 reverse-engineer-anything 分析这个样本」，agent 会去读那份 SKILL.md。
- 想关掉某个：技能里按组开关，或在 `cordis.patch.yml` 里停用对应条目。

### 7.3 想加技能

用「技能」面板的**新建技能向导**（写到用户级目录），或直接把技能目录拷进 `%USERPROFILE%\.dsh\skills\`。外部仓库可用面板的「市场」导入，之后能检查上游更新。

## 8. 本地记忆服务（可选）

插件包**不启动任何后台服务**。ReMe / OpenViking / Hindsight / WeKnora 是独立进程，装不装都能用 DSH，只是记忆与知识库类功能会显示未连接。

| 服务 | 端口 | 装完能得到什么 |
|---|---|---|
| ReMe | 2333 | 自动整理跨会话的事实 / 偏好 / 决定 / 待办 |
| OpenViking | 1933 | 记忆库、资料 URI、共享技能 |
| Hindsight | 8888 | 项目知识页（仓库级累积知识） |
| WeKnora | 8080 | 组织知识库 RAG（要 WSL2） |

安装：解压 `DSH-Plugins-v2.0.0-Services.zip` → 双击 `SETUP-SERVICES.cmd`。只装前两个可以：

```powershell
.\SETUP-SERVICES.ps1 -Only reme,openviking
```

**ReMe 必须额外设模型环境变量**，否则自动记忆会一直报 `Missing credentials`：

```powershell
setx LLM_BACKEND openai
setx LLM_BASE_URL "https://你的中转站/v1"
setx LLM_MODEL_NAME deepseek-v4.1-flash
setx LLM_API_KEY "sk-你的key"
```

设完重启 ReMe（`%USERPROFILE%\.dsh\services\reme\stop.cmd` 再 `start.cmd`）。细节：[`服务部署指南.md`](服务部署指南.md)。

## 9. 常用工作流示例

1. **让它先读懂项目再动手**：把仓库路径丢给会话 → agent 先 `hindsight_search_knowledge_pages` 查历史决定 → 再读代码。
2. **画架构图**：说「用 archify 把这条链路画成可交互 HTML」，产物是单文件 HTML，能导出 PNG。
3. **改 drawio 画布**：打开 `.drawio` → 说「把支付节点挪到右边并加一条失败分支」，走 `drawai-canvas`。
4. **写文档 / 报表**：说「用 office 写一份 docx」，或「读这个 xlsx 后做透视」。
5. **长任务不丢线**：开「工作台」，把场景与交接写进 `%USERPROFILE%\.dsh\workbench\`，每次开新会话先看这面墙。
6. **逆向一个安装包**：`reverse-engineer-anything` 读入口 → `dsh-purge` 排阶段 → 证据落文件。
7. **本地模型试水**：Ollama 面板加载 `qwen3:8b` → 面板内试一句 → 满意了再考虑接进会话。
8. **省钱**：看「成本」面板，把贵模型的会话换成 `deepseek-flash`（改 `agent-default-model`）。

## 10. 更新、备份、回滚、迁移、卸载

### 10.1 v1 用户升级到 v2

用 **C 备份覆盖**（`.\install.ps1 -Mode backup`）：它会先备份你的 `cordis.patch.yml`，再覆盖。技能管理会从 `dsh-skill-hub` + `dsh-my-skill-manager` 换成 `dsh-skill-fusion`（旧包仍在，默认停用）。

### 10.2 v2.x 小版本升级

同样用 C 模式；或者解压新版后用 B 模式（只补缺）。升级后跑一次 `DOCTOR.cmd`。

### 10.3 备份在哪

`%LOCALAPPDATA%\DSHPluginsPack\v2.0.0-windows\backups\<时间戳>\`，含：

- `package.json`、`cordis.yml`、`cordis.patch.yml`、`pnpm-workspace.yaml`、`pnpm-lock.yaml`（安装前原样）
- `cordis.patch.yml.before`（合并前）
- `deps-before.json`（当时的依赖与 bundle 列表）
- `skills\<层>\<技能名>\`（被覆盖的旧技能）

### 10.4 回滚

```powershell
.\install.ps1 -Action rollback      # 或双击 ROLLBACK.cmd
```

它列出所有备份，选一个就还原配置、移除本包新增依赖、把 bundle 列表恢复。**用户数据（会话、记忆、技能个人文件）不动。**

### 10.5 迁移到新机器

1. 新机器装 DSH（同版本内核）。
2. 拿同样的压缩包，走 A 或 B 模式。
3. 想把会话/记忆也搬过去：额外复制 `%USERPROFILE%\.dsh\` 下的 `sessions`、`.credentials.yaml`、`skills`、`workbench`、`services` 数据目录（**服务本体别直接拷**，用服务包重装）。

### 10.6 卸载

```powershell
.\install.ps1 -Action uninstall     # 或双击 UNINSTALL.cmd
```

摘掉本包装的依赖与链接、删掉对应 bundle 条目；保留你的配置、备份、技能与数据。想连持久目录一起清：手动删 `%LOCALAPPDATA%\DSHPluginsPack\v2.0.0-windows`。

## 11. 排障速查

| 症状 | 先做什么 |
|---|---|
| 双击 `INSTALL.cmd` 闪退 | 改用 PowerShell 跑 `.\install.ps1`，能看到完整报错；常见原因是解压不完整或路径太长 |
| `找不到 payload\node_modules` | 压缩包没解压完整，用 7-Zip 重新解压到短路径 |
| `内核版本 ... 不在支持范围` | 先 `DOCTOR.cmd` 看真实版本；确实不是 0.2.x 就走 AI-agent 适配，或 `-ForceKernel` 硬装后自检 |
| `目标 profile 已有其他插件` | 说明选了 A。改用 B（回车）或 C |
| 装完界面没变化 | 完全退出 DSH 再开；再看 `DOCTOR.cmd` 的「本包插件已挂载」 |
| 模型列表空 / 调不通 | 看第 4 节；确认占位符换了、Key 填了、重启过 |
| 侧边栏少了入口 | 对应 bundle 可能被你之前的配置停用了，`DOCTOR.cmd` 看「加载时被跳过的 bundle」 |
| 记忆功能报错 | 服务没装或没起，看第 8 节 |
| 技能列表空 | 技能目录权限或路径不对，看 `%USERPROFILE%\.dsh\skills` 是否存在 |
| 插件报 `restart-required` | 正常，重启 DSH |
| 想把装坏的退回去 | `ROLLBACK.cmd` |

完整版（每个症状的原因与可复制命令）：[`常见问题.md`](常见问题.md)。

## 附录 C · 术语与缩写

| 词 | 意思 |
|---|---|
| bundle | 可整体启停的插件集合，`package.json` 的 `dsh.profile.bundles` 里列着 |
| entry / 条目 | bundle 里的一行实例，有 `id`，`cordis.patch.yml` 按 `id` 定位 |
| patch 层 | `cordis.patch.yml`：在 bundle 默认值之上做覆盖、启停、插入 |
| `link:` | 依赖写法，指向本地目录而不是 npm 版本 |
| API 信任栅栏 | DSH 的路由保护：只允许回环 / 绑定地址 / `--trusted-host` + 浏览器会话 |
| 功能档位 | `feature-profiles` 里的能力手册，按需加载 |
| 持久目录 | `%LOCALAPPDATA%\DSHPluginsPack\v2.0.0-windows`，链接的真实落点 |
