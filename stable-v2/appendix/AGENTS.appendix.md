# 对齐提问协议（ALIGNMENT_PROTOCOL v1.0）

**第一条规则：任何任务动手之前，先按这个任务的难度与广度生成 N 个对齐问题，把方案对齐，再执行。**

N 不是固定值：微改可以 0 问，发版级任务可以几十问。问题是执行参数，不是请示。

**优先级**：本块与其他档位规则冲突时，以本块为准 —— 档位询问走**交互卡片、单独提问**（见 §2.1、§5），不用纯文字问一次。

## 1. 难度分级与问题数量

| 档 | 判据（命中任一即取该档） | 问题数 |
| --- | --- | --- |
| **D0 微改** | 单条命令、只读查询、读文件/配置、单文件小改 | 0–2 |
| **D1 常规** | 单文件功能改动、常规排障、写一份文档、跑一次构建 | 3–6 |
| **D2 跨面** | 多文件多步骤、代码+文档+配置联动、方案取舍、并行分工 | 8–15 |
| **D3 不可逆** | 发版/发布、动全局环境或凭据、删改用户数据、推仓库、重打大包 | 15–30，广度大时最多 50 |

判定取最高项：只要含一个 D3 要素（例如"顺便发版"），整体按 D3 出题。

## 2. 提问分两层：执行参数用卡片，方案问题用清单

### 2.1 第一层：执行参数 —— 单独提问，必须用交互卡片

- 卡片只放这一个问题（必要时并列 ≤3 个参数），选项固定为 `1 快答 / 2 标准 / 3 严格四层推演`，带推荐值与 ≤20 字理由。
- 用户不回 → 按推荐值执行，并在回执里注明"档位按推荐 X 执行"。
- 卡片问题不得与方案问题混在一起，避免用户在长清单里漏掉档位。

### 2.2 第二层：方案问题 —— 编号清单，每问三件

1. **问题**：一句话就能回答，不问开放式的"你觉得怎么样"。
2. **推荐默认值**：可直接执行的那一个（A/B/C 里点名 A）。
3. **一句取舍**：选它得到什么、放弃什么。

分组编号（A 定义与范围 / B 内容与数量 / C 落点与打包 / D 版本与发布 / E 验收与回滚），并在末尾给两条硬提示：

- 「回『全部按推荐』即开工」
- 「只想改关键项就写『第 3 题选 B』，其余按推荐」

### 2.3 何时把方案问题也做成卡片

只有**关键决策 ≤ 4 个**时才用卡片分题弹；超过 4 个一律走文字编号清单，卡片只承担执行参数。

## 3. 一轮收束

- 用户回「按推荐 / 都行 / 你定 / 不用问」→ 立刻执行，不再追问。
- 用户改单 → 只复述被改的项，其余按推荐值执行。
- 方案发生变更（新增目标、换落点、换版本号、换受众）→ 对变更部分重新对齐一次，不得静默改道。

## 4. 不触发白名单（这些直接做，不出清单）

- 纯事实查询、读文件/日志/配置、单条只读命令。
- 用户已在本会话锁定方案，或明确说「直接做 / 别问 / 快 / 按推荐 / 不用问」。
- 已对齐方案内部的下一步（同一个方案不重复问）。
- 紧急排障：先止血再对齐；止血动作不受门禁限制，止血后补对齐。
- 宿主规则已禁止请示的场合（授权、范围、方向类询问）。
- 子任务已被上级 agent 对齐过（brief 里写明结论与档位）。

## 5. 与档位开关的合并（先卡片定档，再出清单）

1. **卡片问档位**（单独一张卡，见 §2.1）。
2. **按档位决定是否出方案清单**：微改静默执行 / 常规出 3–6 问 / 跨面与不可逆出全量清单。

## 6. 执行后的对齐回执

- 哪些**按推荐**执行、哪些**被改单**
- 实测证据（命令输出、哈希、比对结果），不与"应该没问题"混写
- **未验证 / 遗留**项，单独一行列出
- 回滚路径（备份在哪、怎么恢复）

## 7. 子代理与队友

派发 subagent / teammate 时，brief 里必须写：本任务适用 `ALIGNMENT_PROTOCOL v1.0`、难度档 Dx、已对齐的结论清单；子代理不得因为"已对齐"就跳过证据核验，也不得反过来再向用户重复提问。

## 8. 语言与格式

中文、编号、一条一行；超过 15 问时按 A–E 分组，并在开头提示「至少回关键项」。

## 9. 反例（这些做法算违规）

- 用"要不要继续"这类空问题凑数。
- 不给推荐值，把取舍全部推给用户。
- 问完不等回答就动手。
- 对 D0 任务硬凑 20 问。
- 已经把结论对齐过，下一轮又重问一遍。
- 把执行参数塞进几十条方案清单里，用户翻不到。
- 该用卡片时用纯文字、或该用清单时硬塞卡片。
- 把"测试通过"写成"已发布可用"。
