# 环境维护与自检（CL-001 … CL-007）

本文件是本补丁的**逐条手册**：每条都写清「问题 → 判据 → 命令 → 验证 → 回滚」，方便出问题时一条一条对。

判据一栏是本补丁的**安全底线**：判据不满足就只报告、不动手。

---

## CL-001 ReMe 日志按大小切分

- **问题**：ReMe 上游用 loguru，`rotation="00:00"` 只在跨日 0 点切分。常驻进程跑满一天只会产生一个巨型文件（实测 280 MB / 293 MB / 155 MB），一天吃掉几百 MB。
- **判据**：
  - 文件路径匹配 `.../reme/utils/logger_utils.py`；
  - 文件内含 `rotation="00:00"` → 待修；
  - 含 `rotation="100 MB"` → 已经修过，跳过；
  - 两者都没有 → 上游改了写法，只报 `unknown`，不动。
- **命令**：`APPLY.cmd`（或 `apply.ps1`）
- **做什么**：备份成 `<备份目录>/logger__logger_utils.py`，再把 `rotation="00:00"` 全量替换成 `rotation="100 MB"`；写完再读一遍确认命中，否则整体报错。
- **验证**：`Select-String -Path <该文件> -Pattern 'rotation='` 应显示 `rotation="100 MB",`；重启 ReMe 后新日志从启动行正常写，旧文件停止增长。
- **注意**：ReMe 升级会覆盖 `site-packages` → **升级后必须重跑本补丁**。
- **回滚**：`ROLLBACK.cmd`，或把 `logger__logger_utils.py` 覆盖回去。

## CL-002 / CL-003 卸载残留清理

- **问题**：插件从 `bundles` 取消后，`node_modules` 里仍留目录，其中一部分是完全空的壳（0 文件）。
- **判据**：
  - 目标包名在废弃清单里：`dsh-my-skill-manager`、`dsh-shared`、`dsh-skill-hub`；
  - 目录存在且**文件数 = 0** → 删；
  - 目录有文件 → **保留**，只在报告里写 `kept` 和文件数（`-PurgeDeprecated` 才删）。
  - 为什么这么保守：`dsh-shared` 是真实共享库（`kind: library`），pnpm hoisted 布局下很多插件靠它，删了会连锁坏掉。
- **命令**：`APPLY.cmd`；要连有文件的也删，用 `APPLY.cmd -PurgeDeprecated`（报告会标 `purged`）。
- **package.json**：只有真的引用了废弃包时才会改；改前备份 `packagejson__package.json`，写完立即用 `ConvertFrom-Json` 复验，JSON 不合法就整体报错。
- **验证**：目标目录不存在；`package.json` 里 grep 不到这些名字；DSH 重启后插件页正常。
- **回滚**：`ROLLBACK.cmd` 还原 `package.json`；被删的包用 `pnpm add <包名>` 重装（报告里给了建议命令）。

## CL-004 空桶依赖自检（目录在、文件数 0）

- **问题**：`@tt-a1i/archify-dsh` 曾是 0 文件的真实目录，但 `package.json` 里还列着，导致 archify 技能静默失效。
- **判据**：对 `dependencies` / `devDependencies` / `optionalDependencies` / `dsh.bundles` 里每个包，若其目录存在且**递归文件数 = 0** → 判定为「装了但坏了」。
- **命令**：
  - 只报：`APPLY.cmd`
  - 尝试修：`APPLY.cmd -RepairEmpty`（在 profile 目录里跑 `pnpm add <包>@<版本> --prefer-offline`，失败就打印手动命令）
- **跳过规则**：`link:` / `file:` / `workspace:` 这类本地 spec 不自动重装（属于本地源码工程，重装会破坏链接）。
- **验证**：目录文件数 > 0；DSH 重启后技能列表出现对应技能。
- **回滚**：无需回滚（重装是修复动作）。

## CL-005 `feature-profiles` 临时文件

- **问题**：首启生成手册时写入中断会留 `*.tmp`。
- **判据**：`<profile>/feature-profiles/` 下扩展名为 `.tmp` 的文件。
- **命令**：`APPLY.cmd`
- **验证**：该目录只剩正式 `*.md` 与索引文件。
- **回滚**：不需要（中间产物）。

## CL-006 巨型日志

- **问题**：死进程留下的日志能到几百 MB（实测 3 个文件合计 488.9 MB，其中两个是 `Missing credentials` 无限重试刷出来的）。
- **判据**：
  - `<DSH 主目录>/services/*/logs/*.log` 且大小 ≥ `-LogSizeMB`（默认 100）；
  - 文件名尾部的 `_<pid>` 对应进程**已结束** → 可删；
  - 进程还活着 → 一律 `kept-live`。
- **命令**：
  - 只报：`APPLY.cmd`
  - 删除：`APPLY.cmd -PurgeLogs`（可配 `-LogSizeMB 200`）
- **验证**：报告里 `savedBytes` 与目录体积变化一致。
- **回滚**：日志属运行时产物，不备份（删前已确认进程死亡）。

## CL-007 ReMe 记忆 LLM 环境变量

- **问题**：记忆融合长期报 `OpenAIError: Missing credentials.`。ReMe 读的是**用户环境变量** `LLM_BACKEND` / `LLM_MODEL_NAME` / `LLM_BASE_URL` / `LLM_API_KEY`，与 DSH 自己的模型供应商配置是两套独立配置。
- **判据**：只看这四个变量**在不在**（值不回显）。
- **命令**：
  - 只看状态：`APPLY.cmd`
  - 写入：`APPLY.cmd -LlmBaseUrl <...> -LlmModel <...> -LlmApiKey <...>`（三个必须同时给，少一个直接报错且不写）
- **隐私**：Key 只写进用户环境变量；备份里的 `user-env-before.json` 把 Key 记成 `(set, not recorded)`；报告里一律 `masked`。
- **验证**：重启 ReMe 后 `health_check` 200，日志出现 `[AutoMemoryStep] ... has_result=True`。
- **回滚**：`ROLLBACK.cmd` 不还原环境变量（脚本不动系统环境的历史值），改回旧值请参照 `user-env-before.json` 里记录的 `(set)/(unset)` 状态手工设置。

## 报告与备份长什么样

```
%LOCALAPPDATA%\DSHPluginMigration\maintenance-20261029\
  maintenance-report.json          最近一次运行
  runs\20261029-093012.json        每次运行的独立记录
  backup-20261029-093012\          本次备份集
    manifest.json                  条目：restore <- backup
    logger__logger_utils.py
    packagejson__package.json
    user-env-before.json
```

`actions` 数组是本补丁的核心证据：每条都是 `{op, target, action, detail}`，`action` 取值
`patched / skip / unknown / removed / purged / kept / stripped / empty / reinstall(ed|failed|error) / deleted / reported / present / missing / written`。
`-CheckOnly` 时对应变成 `would-*`，并且**不创建任何文件**。

## 与整包的关系（下次重打时要做什么）

`v2.0.2-patch.1` 只把逻辑交到用户手里；等重打整包 `v2.1.0` 时，按下面顺序并进 `install.ps1`：

1. CL-001 的 `rotation` 幂等替换写成独立函数，在**安装 / 升级 / 修复**三条路径都调用；
2. 废弃包名清单进「清理旧版本残留」步骤，并同步摘 `package.json` 引用；
3. CL-004 的「文件数 = 0 ⇒ 视为未安装」并入依赖自检，对所有 bundles 通用；
4. CL-005/006 进收尾清理；
5. 安装向导增加「记忆服务 LLM」页，只写用户级环境变量（不打包密钥）；
6. 打包后自检：`rotation="100 MB"` 命中、废弃包名无目录无引用、每个 bundle 文件数 > 0、`LLM_*` 四个变量在用户级可见（值不回显）。

在此之前，这个补丁就是那份「可执行清单」。
